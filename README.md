# TRPGセッションツール向け、クラウド素材保管庫「TakuVault」


## サービス概要
TakuVault は、TRPGセッションツールで使用した背景・カットイン・BGM等の素材をクラウド上に保存し、 「どのセッション / どのシーン / どの役割で使った素材か（Where used）」を逆引きできる素材保管庫です。 ※MVPでは Cocofoliaのみ を対象にし、部屋連携は room_urlの参照保存（同期やAPI連携は行わない）とします。


## このサービスへの思い・作りたい理由
趣味のTRPGのKPとして部屋を作る中で、使用した素材を手元で雑に管理してしまい、「いつ・どのシーンで使った素材か分からない」「良かったBGMや背景が見つからない」という問題が発生することがありました。 既存ツールにも素材保存機能はある一方、シーン単位での分割管理 / リネーム / タグ付け / 逆引き検索がなく、その点を不満に感じています。 そこで、複数セッション・複数ツールに跨って素材を整理できる「クラウドの素材保管庫」を作りたいと考えました。


## ユーザー層について
* TRPGのKP/GMで、セッション準備の素材管理を効率化したいユーザーをターゲットにしています。
* ライトユーザー：素材をクラウドに分かりやすくまとめておきたい
* ヘビーユーザー：複数セッション/複数ツールの素材を一元管理したい


## サービスの利用イメージ
* セッションのURLリンク（room_url）を登録することで、アプリケーションからセッションにリダイレクトできます。
* 素材をアップロードし、リネームやタグ付けを行えます。
* ファイル名/リネーム名で検索でき、タグ等で絞り込みできます。
* 素材詳細から「どのセッション/どのシーン/どの役割で使用したか（Where used）」を逆引きできます。


## ユーザーの獲得について
* SNS（X など）でTRPG関連のハッシュタグを用いて発信し、特にセッション準備を行うKP/GM層に向けて、以下を主軸に訴求します。
* セッション素材（背景/カットイン/BGM等）を 一元管理できること
* 「どのセッション / どのシーン / どの役割で使ったか」を追跡できること（Where used）
* 次回以降のセッション準備における 検索・再利用の効率化


## サービスの差別化ポイント・推しポイント
TakuVaultの最大の特徴は、素材を単に保存するだけでなく、 Where used（素材がどのセッション/シーン/役割で使われたか）を記録し、素材側から逆引きできる点です。 このアプリケーションでは、「あの時の背景/BGMどこに保存したかな？」の疑問を即座に検索、逆引き機能によって解決できます。
また、将来的には複数のセッションツール（Cocofolia以外）にも対応し、ツールを跨いだ素材管理を可能にすることで継続利用の価値を高めていく想定です。


## 機能候補

### MVPリリース
* ユーザー登録 / ログイン、ログアウト機能（Devise）を搭載し、ユーザーごとにアカウントと素材を紐づけて管理できるようにします。
* MVPリリース時点では、対応するセッションツールは Cocofolia のみとします。
* ルーム連携は同期ではなく、セッションツールの部屋URL（room_url）を保存して参照できる形に留めます。
* MVPでは、素材（Asset）をクラウドへ永続保存し（Cloudflare R2）、アップロード→参照→削除が成立する状態を優先します。
* MVPのWhere used は最小導線として、素材詳細から使用先（セッション/シーン/役割）を確認できる状態を目指します。
* 検索/絞り込み/タグは MVP では実装せず、本リリース以降の機能として扱います。

## 容量・アップロード上限（Quota）
MVPでは、アップロード時に以下の上限をサーバ側で判定し、**1つでも違反があれば全体を拒否（all-or-nothing / fail-closed）**します。
* 1ファイル上限：50MB（10進。50,000,000 bytes）
* 総容量上限：500MB（10進。500,000,000 bytes。**ユーザー単位 / Asset原本合計**）
* 1回のアップロード上限：30ファイル（複数ファイル選択1回あたり）
* 1回のアップロード合計上限：200MB（10進。200,000,000 bytes。複数ファイル選択1回あたり）

## ストレージ（preview）
- preview環境（`RAILS_ENV=production`）では、Active Storage は **Cloudflare R2**（service key `:r2`）を使用します。
- 環境は preview の単一構成です。staging / production の分離は行っていません。

## バックグラウンドジョブ（必須）
- キュー基盤：Solid Queue（DB-backed、**primary DB 同居**）
- Render は 2 プロセス運用です。
  - Web（Rails）
  - Worker（`bin/jobs start`）
- `purge_later` / `analyze` / `variant(transform)` は Worker 前提です。Worker 停止時はジョブが滞留し、削除・解析・派生物生成が完了しません。

## DBマイグレーション
- ローカルでは、コンテナ内で `docker compose exec web bin/rails db:migrate` を実行します。
- preview環境では、デプロイ時に `bin/rails db:migrate` を実行します。

### 判定タイミング
* 作成前（リクエスト処理時点）に判定し、超過は拒否します。
* アップロード方式は **サーバ経由 multipart** に統一し、Direct Upload は採用しません。

### 参照（正本）
* 容量・上限の定義と算定ルール：ADR-0013
* 許可形式・判定方式・エラーハンドリング：ADR-0014
* Direct Upload 不採用（サーバ経由 multipart 統一）：ADR-0012

### 本リリース以降
* (その他のセッションツール対応は本リリース前に、ユドナリウム、TRPGスタジオ、Quoridorn を検討中)
* ファイル名/タイトル等による検索、タグ等による絞り込み、フィルタリング・ソート
* 素材のリネーム、タグ編集機能（複数選択対応）
* 素材の移動（セッション/シーン/役割間のドラッグ&ドロップ対応）

### 将来の検討機能
* 素材の自動タグ付け機能（拡張子(jpg, png, mp3, wav, pdf等を判別)、音声素材の長さ等に基づく）
* また、MVPでは見送る想定ですが、投下した動画素材を APNG+MP3に変換し、Cocofolia等でカットインとしてすぐ利用できる機能も検討しています。


## 使用する技術スタック
* 使用するフレームワーク: Ruby 3.x, Rails 7.x（フルスタック）
* データベース: PostgreSQL
* デプロイ先: Render（Web / Worker）
* ストレージ / ライブラリ: ActiveStorage, Cloudflare R2（S3互換）, Solid Queue
