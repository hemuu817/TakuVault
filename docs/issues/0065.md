## Body

## 目的（このIssueで達成する価値）
素材一覧でタグをスイッチ（トグル）選択して絞り込みできるようにし、既存の状態（roleフィルタ、Session/Sceneスコープ選択）を維持したまま表示結果へ反映する。

## 前提（この画面の状態）
- Session/Scene は「絞り込み」ではなく **切替（スコープ選択）**（既決）
- role は **フィルタ**（既決）
- 本Issueで追加する tag は **フィルタ**（roleと同列）
- フィルタ（role/tag）変更時、Session/Sceneスコープ選択は維持される（リセットしない）
  - ※Session切替でSceneが未選択に戻る仕様は別Issueの責務（既決）

## 仕様（適用対象の固定）
- タグ条件は **Asset** に対して適用する（Asset集合を絞る）
※既存のrole/Session/SceneとAND合成
- 表示は Usage（葉）だが、表示対象のUsageは「絞り込まれたAssetに属するUsage」に限定される（Usage自体をタグで直接絞らない）

## スコープ
**含む**
- UI（MVP最小）
  - 素材一覧画面に「タグスイッチ」領域を追加（チェックボックス/トグル）
  - 候補は policy_scope(Tag)（= current_user.tags）のみ
  - 選択タグはクエリパラメータで保持（例：tag_ids[]=1&tag_ids[]=2）
  - **既存の状態（role / session_id / scene_id）をクエリに保持し、タグ操作で落とさない**
    - 例：フォームhidden/リンク生成で role, session_id, scene_id を引き継ぐ
- 絞り込み仕様（意味論を固定）
  - ベーススコープ：policy_scope(Asset)
  - スコープ選択（Session/Scene）が指定されている場合は、その条件を適用する
  - role が指定されている場合は、その条件を適用する
  - tag_ids が1件以上ある場合は、タグ条件を適用する
  - **最終結果はすべてANDで合成**する：
    - （scope：session/scene） AND （role） AND （tags）
  - tags の意味論：**選択タグをすべて含む素材のみ表示（AND）**
  - tag_ids が空/未指定ならタグ条件なし
- tag_ids の正規化（MVP固定）
  - tag_ids は policy_scope(Tag).where(id: tag_ids) で正規化し、有効タグのみ適用する
  - 有効タグが0件の場合は「タグ条件なし」として扱う（MVP固定）
- クエリ設計（固定）
  - Query Object の返り値は Asset の ActiveRecord::Relation とする
  - role/session/scene は「該当Usageが存在するAsset」に絞る条件として適用する
  - tags は asset_tags/tags JOIN で適用する
  - 複数タグANDは GROUP BY assets.id HAVING COUNT(DISTINCT tags.id)=選択数（または同等のサブクエリ）で実現する
  - JOIN により重複が出るため、必要に応じて **assets.id で distinct** を適用する（事故重複のみ排除）
  - N+1回避のため tags を preload/includes する
- 遅延ロード契約（該当画面が遅延ロードの場合）
  - 遅延ロードの取得リクエストには tag_ids と role（任意）を引き継ぐ（メイン表示と同一条件）
- 認可（固定）
  - タグ候補は policy_scope(Tag) のみ
  - tag_id 混入（他ユーザー）で他人のデータが表示されない（fail-closed）
- 0件表示
  - 結果0件の場合「該当する素材がありません」を表示

**含まない**
- タグの作成/削除/付与（#32の責務）
- OR条件（いずれか含む）はMVP外（ANDのみ）
- 条件保存（スマートフィルタ等）

## 受け入れ条件（Yes/No）
- [ ] 素材一覧にタグスイッチが表示される（候補は自分のタグのみ）
- [ ] タグ未選択では、既存条件（role / session/sceneスコープ）だけが適用される
- [ ] タグを1つ選ぶと、**既存条件に加えて**そのタグを持つ素材のみ表示される
- [ ] タグを複数選ぶと、**既存条件に加えて**選択タグをすべて含む素材のみ表示される（AND）
- [ ] role が有効な状態でタグを切り替えても、role が維持され、結果に反映され続ける
- [ ] session/scene スコープが有効な状態でタグを切り替えても、スコープが維持され、結果に反映され続ける
- [ ] tag_ids に他ユーザーのIDや不正値が混ざっても例外にならず、他ユーザーのデータは出ない（fail-closed）
- [ ] tag_ids が全て無効（policy_scope(Tag)で0件）の場合、タグ未選択と同じ挙動になる（MVP固定）
- [ ] 選択状態（tag_ids/role/scope）がURLに保持され、リロードしても維持される
- [ ] 結果0件時にメッセージが表示される

## DoD（完了条件）
- [ ] タグ絞り込みロジックが Query Object に集約されている（role/scopeとの合成含む）
- [ ] 複数タグANDが GROUP BY/HAVING（または同等サブクエリ）で成立している
- [ ] JOIN時に assets.id で重複排除できており、同一Assetが重複表示されない
- [ ] tags を preload/includes して N+1 を出さない
- [ ] System spec で「AND仕様」「role維持」「scope維持」「認可」「0件表示」を担保する

## 失敗ケース（最低3つ）
- [ ] タグ操作で role が落ちる／反映されない（状態保持不備）
- [ ] タグ操作で session/scene スコープが落ちる／反映されない（状態保持不備）
- [ ] 複数タグが OR 扱いになり、意図より広い結果が出る（AND仕様違反）
- [ ] JOINの影響で同一Assetが重複表示される（重複排除不足）
- [ ] 他ユーザーのtag_id混入で他人の素材が表示される（認可漏れ）

## 最小テスト/検証
**Model/DB**
- [ ] tag_ids が1件のとき：既存条件（role/scope）がある場合、それらとANDで絞られる
- [ ] tag_ids が複数のとき：選択タグAND + 既存条件ANDで絞られる
- [ ] GROUP BY/HAVING（または同等）によりANDが成立する
- [ ] assets.id の重複排除により重複が出ない

**Policy**
- [ ] policy_scope(Tag)/policy_scope(Asset) 起点で他人のタグ/素材が候補にも結果にも出ない

**System**
- [ ] role を指定した状態でタグを切り替えても role が維持され、結果に反映される
- [ ] session/scene スコープを指定した状態でタグを切り替えてもスコープが維持され、結果に反映される
- [ ] タグ複数選択がANDで効く
- [ ] tag_ids が全て無効でも例外にならず、タグ未選択と同じ挙動になる
- [ ] 0件表示が出る
