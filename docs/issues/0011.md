# #11 認可方式の固定（Pundit導入・適用ルール固定）

## 目的
以後の全CRUDで認可漏れを発生させないため、認可方式を Pundit に固定し、`policy_scope/authorize` の適用と漏れ検知を“仕組み”として確立する。

## スコープ
**含む**
- Pundit導入（install、ApplicationPolicy/Scope）
- ApplicationControllerにPundit組み込み（`include Pundit::Authorization`）
- 認可適用ルール固定
  - 【区分定義】コレクション系 action / メンバー系 action を定義し、適用ルールを固定する
  - コレクション系（例：index、将来のsearch/uncategorized等）: `policy_scope(Model)` 必須
  - メンバー系（例：show/new/create/edit/update/destroy）: `authorize(record)` 必須
  - 【素材詳細の正本】素材詳細（“Board UI”を含む）は `AssetsController#show` を正本とし、Board表現は view/partial の責務とする

- 認可漏れ検知（after_action）
  - `verify_authorized` / `verify_policy_scoped` による “呼び忘れ検知” の方針を固定する
  - ただし、これは開発補助（プログラマエラー検知）であり、認可の代替機構ではない
  - コレクション系 action の一覧は「index固定」ではなく、コレクション系 action を追加した場合は一覧へ追記する（例：[:index, :search, :uncategorized]）
  - 条件分岐で検知を回避したい場合は `skip_authorization` / `skip_policy_scope` を使用する（skip_after_action の乱発はしない）
  - 重要：`verify_*` の「実際の有効化」は #12（各Policy/Scope整備）完了と同一変更セットで行う（#11では方針と実装枠のみ用意し、デフォルトではOFF）
- 未認可時の共通ハンドリング方針を固定（本PJは 404 に寄せる）
  - 404 に寄せるのは `Pundit::NotAuthorizedError` のみ（= 認可は実行され拒否されたケース）
  - 以下は “開発ミス検知” のため rescue しない（握りつぶさない）
    - `Pundit::AuthorizationNotPerformedError`（authorize呼び忘れ）
    - `Pundit::PolicyScopingNotPerformedError`（policy_scope呼び忘れ）
    - `Pundit::NotDefinedError`（Policy/Scope未定義）
 
**含まない**
- 所有権（user_idスコープ）や各リソースPolicyの中身 ※ #12
- 管理者/共有/招待
- 2FA等
- ActiveStorage の実体配信経路を「認証必須」にする対応（Authenticated Controllers / 既定ルート無効化等）
  - MVPでは「認可済みAssetからのみURL生成」＋URLを秘匿情報（bearer）として扱う前提で進める
  - 本リリースで別Issueとして、認証付き配信（Authenticated Controllers）へ移行する方針

## 運用メモ（実装者向け：迷いどころの固定）
Issue本文の方針を、実装時に迷わない粒度まで落とした運用ルール。本文と矛盾する場合は本文を優先する。

### 1) 対象/除外は ApplicationController に集約
- Devise は Pundit 適用対象外（controller側で `skip_after_action` を乱発しない）
- Healthcheck / PWA 等の例外は `PUNDIT_EXCLUDED_CONTROLLERS` に一元管理する（追加したら必ず追記）

### 2) 認可方式の区分（index固定ではない）
- コレクション系 action は **`policy_scope(Model)` 必須**
  - 対象 action は `PUNDIT_POLICY_SCOPED_ACTIONS` で **一覧管理**
  - コレクション系 action を追加したら **必ず** `PUNDIT_POLICY_SCOPED_ACTIONS` に追記する（例：search / uncategorized）
- メンバー系 action は **`authorize(record)` 必須**
  - 原則：`PUNDIT_POLICY_SCOPED_ACTIONS` に含まれない action は **メンバー系扱い**（authorize必須）

### 3) 推奨実装パターン（安全な型を固定）
- 既存レコード（show/edit/update/destroy）
  - 原則：`record = policy_scope(Model).find(params[:id])` → `authorize(record)`
  - `Model.find` を先に呼ばない（所有権スコープ逸脱の事故を防ぐ）
- 未保存レコード（new/create）
  - **案A：レコード方式に統一**
    - `record = Model.new(permitted_params)`
    - `record.user = current_user` を **authorizeより先**にセット（重要）
    - `authorize(record)`

### 4) 呼び忘れ検知（verify_*）
- #11では “枠だけ” 用意し **デフォルトOFF**
- `pundit_verify_enabled?` でガードし、`verify_*` は `pundit_enabled? && pundit_verify_enabled?` のときのみ実行
- #12（各Policy/Scope整備）と **同一変更セットでON** にする
- ON後は authorize/policy_scope の呼び忘れが **開発ミス例外として顕在化**する（意図通り）

### 5) 例外（意図的に認可を省略する場合）
- controller 単位の `skip_after_action` は禁止（例外は集約定数で管理）
- 分岐で意図的に回避する場合のみ、action 内で `skip_authorization` / `skip_policy_scope` を使用
- “一時しのぎ” 目的で使わない（仕様として不要な場合に限定）

### 6) 未認可時の共通ハンドリング（404寄せ）
- 404寄せは `Pundit::NotAuthorizedError` のみ（= 認可は実行され拒否されたケース）
- 開発ミス検知の例外は rescue しない（握りつぶさない）
  - `Pundit::AuthorizationNotPerformedError`
  - `Pundit::PolicyScopingNotPerformedError`
  - `Pundit::NotDefinedError`
