# #11 認可方式の固定（Pundit導入・適用ルール固定）

## 目的
以後の全CRUDで認可漏れを発生させないため、認可方式を Pundit に固定し、`policy_scope/authorize` の適用と漏れ検知を“仕組み”として確立する。

## スコープ
**含む**
- Pundit導入（install、ApplicationPolicy/Scope）
- ApplicationControllerにPundit組み込み（`include Pundit::Authorization`）
- 認可適用ルール固定
  - index: `policy_scope(Model)` 必須
  - show/new/create/edit/update/destroy: `authorize(record)` 必須
- 認可漏れ検知（after_action）
  - `verify_authorized`（index以外）
  - `verify_policy_scoped`（index）
- 未認可時の共通ハンドリング方針を固定（本PJは 404 に寄せる）

**含まない**
- 所有権（user_idスコープ）や各リソースPolicyの中身 ※ #12
- 管理者/共有/招待
- 2FA等

## 受け入れ条件（Yes/No）
- [ ] Punditが導入され、全コントローラで利用できる
- [ ] indexはpolicy_scope起点、その他はauthorize必須がルールとして固定されている
- [ ] 認可漏れは `verify_*` により検知される（漏れたら落ちる）
- [ ] 未認可アクセスは共通ハンドラで 404 に寄せる（情報露出しない）
- [ ] 例外（Devise等）は個別skip乱発せず、条件分岐で集約されている

## DoD
- [ ] `after_action :verify_authorized, except: :index, unless: :devise_controller?`
- [ ] `after_action :verify_policy_scoped, only: :index, unless: :devise_controller?`
- [ ] `rescue_from Pundit::NotAuthorizedError` を共通実装し 404 に寄せる
- [ ] 実装パターンが固定されている（例：showは `policy_scope(...).find` → `authorize`）
- [ ] 最小テストがCIで安定して通る（漏れ検知と未認可404）

## 最小テスト/検証
- [ ] 未認可時に 404 になる（共通ハンドラ）
- [ ] 認可漏れ（authorize/policy_scope未実施）が `verify_*` で検知される（方式の確認）
