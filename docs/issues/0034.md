# (26) クラウド永続ストレージ構成（ActiveStorage + Cloudflare R2）

## 目的
Render（Docker）上で、R2（S3互換）を正として  
「アップロード → 参照 → 再デプロイ後も参照可能（永続） → 削除（purge_later）」が成立する状態を確立し、Phase 0（Asset CRUD / 削除整合）が環境差分で止まらないようにする。

## 前提（正本）
- 環境の呼称・分離方針：**ADR-0008**
- ActiveStorage（R2）/ Solid Queue / Render運用：**ADR-0009**
- job基盤の一般方針：**ADR-0005**（ただし staging 記述は ADR-0008 の読み替えルールを適用）

## スコープ
**含む**
- ADR-0009 に従った R2（ActiveStorage）設定の適用
- ADR-0009 に従った DB-backed job基盤 + worker 稼働の成立
- preview（単一環境）での最小疎通（Verification参照）
- env一覧・起動方法・検証手順の文書化（README/docs）

**含まない**
- 上限値（サイズ/許可Content-Type/拡張子）の確定：**(27) 容量/ファイル上限方針**
- 不正ファイル拒否（実装・テスト）：Asset側（Phase 0の該当Issue）
- アップロードUI：Asset側（Phase 0の該当Issue）

## 受け入れ条件（Yes/No）
- [ ] ADR-0009 の設定により、Render環境で 1ファイルのアップロード→参照が成立する
- [ ] 再デプロイ後も参照できる（永続）
- [ ] 削除後、参照不能になり、R2上の実体削除・DB残骸化なしが確認できる
- [ ] worker が稼働し、`purge_later` が滞留しない
- [ ] Direct Upload 不採用が docs/README に明記されている
- [ ] “単一環境（preview）” 前提で本文・docs が矛盾していない（ADR-0008準拠）

## DoD
- [ ] ADR-0008/0009 を正本として参照関係が成立している（Issue本文に詳細再掲しない）
- [ ] Render に Web/Worker の2プロセスが存在し、worker が常時稼働している（ADR-0009準拠）
- [ ] README/docs に env一覧・起動方法・検証手順が記載されている
