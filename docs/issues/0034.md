# #34 (26) 本番ストレージ構成（ActiveStorage + Cloudflare R2 + Solid Queue）

## 目的
Render（Docker / **単一環境: preview**）上で、Cloudflare R2 を ActiveStorage の永続ストレージとして成立させる。  
あわせて、`purge_later` / `analyze` を処理するジョブ基盤（Solid Queue + Worker）を成立させ、Phase 0 の Asset CRUD / 削除整合が **環境差分で止まらない状態** にする。

このIssueは、**preview 環境で「アップロード → 参照 → 再デプロイ後も参照可能（永続） → 削除後の後処理が流れる」** ことを確認するためのものとする。

## 前提
- preview は Render 上の **単一環境** とし、呼称は preview、Rails実行モードは `RAILS_ENV=production` とする
- ActiveStorage の本番ストレージは **Cloudflare R2** を正とする
- Direct Upload は採用せず、**サーバ経由 multipart** に統一する
- `purge_later` / `analyze` / `variant(transform)` は Worker 前提であり、Worker 停止時は滞留する
- queue DB 分離は行わず、**Solid Queue は primary DB 同居**とする

## Verification
ADR-0012 / ADR-0005 の手順に従い、少なくとも以下を手動確認する。

1. preview で Web / Worker が起動していること
2. 小さいファイルを 1 つアップロードできること
3. 一覧 / 詳細で参照できること
4. 再デプロイ後も同じ添付を参照できること
5. 削除後、画面上で参照不能になり、R2 実体削除 + Blob / Attachment 非残骸化が確認できること
6. Worker 稼働中に `purge_later` / `analyze` / `variant(transform)` が滞留しないこと
7. development / test では R2 に接続せず、ローカルservice で動作すること
