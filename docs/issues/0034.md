# #34 (26) 本番ストレージ構成（ActiveStorage + Cloudflare R2 + Solid Queue）

## 目的
Render（Docker / **単一環境：preview**）上で、R2（S3互換）を正として  
「アップロード → 参照 → 再デプロイ後も参照可能（永続） → 削除（purge_later）」が成立する状態を確立し、Phase 0（Asset CRUD / 削除整合）が環境差分で止まらないようにする。

## 前提（正本）
- 環境の呼称・分離方針：**ADR-0011**
- ActiveStorage（R2）/ Solid Queue / Render運用：**ADR-0012**
- job基盤の一般方針：**ADR-0005**

## 決定事項（最終）
### ストレージ（ActiveStorage / R2）
- 提出要件の「本番URL提出」は **デプロイ済みアプリURL（Render等）** を指し、**R2バケットをPublic公開する要件ではない**
  - よって R2 は **Private前提** とする（Publicは避ける）
- preview（`RAILS_ENV=production`）の Active Storage は **R2（service key `:r2`）を使用**（詳細はADR-0012）
- development / test（および production 以外）は **R2 を参照しない**（Disk等のローカルserviceを使用）
  - 目的：ローカル操作で本番データを破壊しない（安全策）
- R2互換の事故回避として **path-style（`force_path_style: true`）** を採用（詳細はADR-0012）
- R2接続は env から注入する（例）
  - `R2_ENDPOINT`, `R2_BUCKET`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_REGION=auto`
- Direct Upload は **不採用**（サーバ経由 multipart に統一）

### ジョブ基盤（purge_later / analyze の成立条件）
- `purge_later` / `analyze` を成立させるため、本番（preview）でジョブ基盤を **用意必須**
  - Solid Queue + Web/Worker、Worker=`bin/jobs start`、default queue 統一（詳細はADR-0012）
- Worker停止時は purge/analysis が滞留し、削除整合が崩れるため **常時稼働前提**

### Solid Queue のDB方針 / マイグレーション運用
- Solid Queue は **primary DB 同居（queue DB 分離しない）**（詳細はADR-0012）
- マイグレーション正本は **`db:migrate`（コンテナ内実行）**（詳細はADR-0012）
