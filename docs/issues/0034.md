# X-01（#34）本番ストレージ方針（R2 + ActiveStorage + Worker）

## 目的
本番/staging相当で「アップロード→参照→削除」が成立するストレージ構成とジョブ基盤を固定し、Epic D が環境差分で止まらない状態にする。

## 前提（このIssueで固定）
- 本番は Render（Docker）
- 永続ストレージは Cloudflare R2（S3互換）+ ActiveStorage
- Direct Upload は使わない（サーバ経由multipart）
- job基盤は **DB-backed**（Redis不要）+ **workerプロセスあり**
- staging/prod は **R2バケット分割**
- Rails は job基盤の採用要件を満たす minor に寄せる（例：7.1+）

## スコープ
**含む**
- `storage.yml` / env 設計（stg/prodバケット分割込み）
- Render で web/worker を別プロセス起動できる状態
- staging相当で「アップロード→参照→削除（purge_later相当）」の最小疎通
- 設定/検証手順の文書化

**含まない**
- 上限値（サイズ/許可Content-Type/拡張子）の最終確定（X-02）
- アップロード安全性（拒否条件の実装）（Epic D）
- アップロードUI（Epic D）

## 受け入れ条件（Yes/No）
- [ ] stg/prod の R2 バケットが分離されている（混入しない）
- [ ] staging相当で 1ファイルアップロード→参照が成立（再デプロイ後も参照可能）
- [ ] worker が稼働し、ジョブが滞留しない
- [ ] purge_later 相当の削除が完了し、DB側（Attachment/Blob）が残骸化しない
- [ ] 必要な環境変数が定義され、Render 側に設定できる
- [ ] Direct Upload 不採用が明記されている

## DoD
- [ ] `storage.yml` が stg/prod を切替できる（バケット分割）
- [ ] queue_adapter（DB-backed）を設定し、worker 起動コマンドを固定
- [ ] Render で web/worker の起動が分離できる
- [ ] README/docs に env一覧・起動方法・検証手順を記載
