# Issue #34: (26) 本番ストレージ構成（ActiveStorage + Cloudflare R2）

- State: OPEN

## Body

## 目的
preview 単一環境（`RAILS_ENV=production`）で、ActiveStorage の永続ストレージを Cloudflare R2 に固定し、Render 上で

- アップロード
- 参照
- 再デプロイ後も参照可能（永続）
- ActiveStorage 関連ジョブの完走
- 削除整合のための基盤成立

を確認できる状態を作る。

本Issueは、Phase 0 の「Cloudflare R2 へ永続保存できる」を成立させるための環境・運用基盤を扱う。

## 背景
- Phase 0 の優先目標は、Asset を Cloudflare R2 に永続保存できること。
- 本Issueは、Asset CRUD / 削除整合が環境差分で止まらないようにするための基盤側Issueである。
- 実装詳細は ADR-0012 を正本とし、Issue本文ではスコープ・受け入れ条件・進捗確認に集中する。

## 正本 / 関連
- ADR-0011：環境の呼称・分離方針（単一環境 preview）
- ADR-0012：ActiveStorage（R2）/ Solid Queue / Render運用の正本
- ADR-0005：job基盤の一般方針と最小検証手順
- GitHub #24 / docs/issues/0024.md：Asset削除整合性

## In Scope
- preview 単一環境で ActiveStorage の永続先を R2 にする
- preview 環境で ActiveJob 基盤を成立させ、ActiveStorage 関連ジョブを完走できるようにする
- Render 上で Web / Worker の2プロセス運用を成立させる
- 再デプロイ後も添付参照が維持されることを確認する
- docs / README / runbook の参照導線を整える
- GitHub #24 の削除整合を支える基盤が preview 環境で成立することを確認する

## Out of Scope
- staging / production の複数環境分離
- バケット分割
- 容量 / 形式 / 413 / 422 の仕様確定や実装詳細
- Asset 側の不正ファイル拒否実装
- 削除整合の仕様本体
- Epic G（MVP外）の変換機能
- envキー一覧・起動コマンド・詳細な検証手順の再掲

## 決定事項
- 環境は preview 単一とし、Rails 実行モードは `RAILS_ENV=production` とする
- preview 環境の ActiveStorage は Cloudflare R2 を永続ストレージとして使う
- Direct Upload は採用しない。アップロードはサーバ経由 multipart に統一する
- ActiveStorage 関連ジョブを処理するため、preview 環境ではジョブ基盤を必須とする
- 本Issueの実装詳細は ADR-0012 を正本とする
- 削除整合の仕様本体は GitHub #24 / docs/issues/0024.md を正本とする
- 容量 / 形式 / 413 / 422 は GitHub #35 / docs/issues/0035.md を正本とする
- R2 の addressing style は ADR-0012 の規約に従う
