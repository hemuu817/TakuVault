## 目的
Phase 0 の「アップロード→参照→削除」を安全に成立させるために、容量・上限・形式制限を固定し、
サーバ側で確実に拒否できる状態にする。

## 前提（正本）
- 容量・上限の定義と算定ルール：**ADR-0013**
- 許可形式・判定方式・エラーハンドリング：**ADR-0014**
- Direct Upload 不採用（サーバ経由 multipart 統一）：**ADR-0012**
- 対象は Asset アップロード（サーバ経由 multipart）のみ
- 1ファイル=1Asset（複数選択はファイル数分のAssetレコードを作る）
- 具体的な拒否実装は Phase 0 の Asset CRUD 側 Issue で行う（本Issueは方針の固定が主目的）
- DB制約で守れない領域（添付サイズ/形式/総容量）はアプリ層で拒否する

## 固定仕様（MVP）

- 1ファイル上限：50MB（10進。50,000,000 bytes）
- 総容量上限：500MB（10進。500,000,000 bytes。ユーザー単位 / Asset原本合計）
- 1回のアップロード上限：30ファイル（複数ファイル選択1回あたり）
- 1回のアップロード合計上限：200MB（10進。200,000,000 bytes。複数ファイル選択1回あたり）
- all-or-nothing（fail-closed）：複数選択時、1つでも違反があれば全体拒否
- 判定タイミング：作成前（リクエスト処理時点）に判定して拒否

## 算定ルール（要点）
- 総容量＝ユーザーの Asset 原本（ActiveStorage 添付）合計（孤児Blobは対象外）
- 同時アップロードの競合は排他（ユーザー行ロック等）で破綻させない
