## Body

## 目的
Phase 0 の「アップロード→参照→削除」を安全に成立させるために、容量・上限・形式制限を固定し、
サーバ側で確実に拒否できる状態にする。

## 前提（正本）
- 容量・上限の定義と算定ルール：**ADR-0010**
- 許可形式・判定方式・エラーハンドリング：**ADR-0011**
- Direct Upload 不採用（サーバ経由 multipart 統一）：**ADR-0009**
- 対象は Asset アップロード（サーバ経由 multipart）のみ
- 1ファイル=1Asset（複数選択はファイル数分のAssetレコードを作る）
- 具体的な拒否実装は Phase 0 の Asset CRUD 側 Issue で行う（本Issueは方針の固定が主目的）
- DB制約で守れない領域（添付サイズ/形式/総容量）はアプリ層で拒否する

## スコープ
**含む**
- ADR-0010/0011 の内容を「固定仕様」として確定
- docs/README に固定仕様を明記（利用者向け・運用向け）
- Phase 0 の Asset 側 Issue に参照関係を追加

**含まない**
- 拒否ロジックの実装（Phase 0 の Asset 側 Issue）
- UI/UX（同上）
