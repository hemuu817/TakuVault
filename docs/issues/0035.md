# #35 (23) 容量/ファイル上限方針（MVP：固定値 / 容量表示UIなし）

## 目的（このIssueで達成する価値）
アップロード時に「単体サイズ」「一括投入数」「ユーザー総容量」を固定値で制限し、**サーバ側で確実に拒否**できるようにする（コストと安全性の担保）。

## スコープ
**含む**
- 上限制限（MVP固定値）
  - 単体ファイル最大サイズ：**25MB**
  - 1回の一括投入ファイル数上限：**20件**
  - ユーザー総容量上限（添付合計）：**500MB**
- サーバ側検証で拒否する（クライアント依存にしない）
  - 単体サイズ超過 / 件数超過 / 総容量超過はアップロードを受け付けずエラー
- 複数ファイル投入は **事前見積もり → 一括判定 → 全失敗** を原則とする
  - 上限を超える場合、途中まで作成して残り失敗、を禁止（中途半端なAssetを残さない）
- エラー表示（UIなしで自己解決できる最低限）
  - どの制約に違反したか（単体/件数/総容量）を明示
  - 上限値（例：総容量 500MB）を明示
  - 次の行動（不要な素材を削除して再試行）を明示
- 実装方針（MVP）
  - 上限値は定数（config/initializer等）に集約し、二重管理しない
  - 総容量の算出は ActiveStorage の blob.byte_size 合計を用いる（既存+追加分で判定）
  - 並行アップロード競合はMVPでは“破綻しない”範囲に留める（厳密な同時排他は将来）

**含まない（MVP外）**
- ダッシュボードでの使用量/残容量/プラン表示（本リリース後に対応）
- プラン切替（無料/有料）による上限変更UI、課金/請求
- 使用量のリアルタイム更新、監査/GCバッチ

## 受け入れ条件（Yes/No）
- [ ] 単体ファイルが25MBを超える場合、サーバ側で拒否される
- [ ] 1回のアップロードで20件を超える場合、サーバ側で拒否される
- [ ] ユーザーの添付合計が500MBを超えるアップロードはサーバ側で拒否される（既存+追加で判定）
- [ ] 超過時、エラーに「制約種別（単体/件数/総容量）」と「上限値」が表示される
- [ ] 複数投入で上限超過した場合、Assetが一部だけ作成されない（全件失敗）
- [ ] 上限値がコード上の単一箇所で管理されている（定数の二重管理がない）
- [ ] 1ファイル=1Asset を維持したまま、安全に失敗できる（例外で落ちない）

## DoD（完了条件）
- [ ] Model/Serviceレイヤで上限チェックが実装されている（Controllerにベタ書きしない）
- [ ] 総容量チェックが「既存+追加」で判定される
- [ ] System spec で単体/件数/総量の拒否が担保される
- [ ] 失敗時に中途半端なAsset/添付が残らない（順序/トランザクションで担保）

## 失敗ケース（最低3つ）
- [ ] 単体サイズ超過なのに受け入れてしまい、大容量ファイルが残る
- [ ] 総容量超過なのに受け入れてしまい、ストレージが青天井になる
- [ ] 一括投入の途中で一部だけ作成され、ユーザーが混乱する（部分成功）

**Model/DB**
- [ ] 単体サイズ超過をサービスで弾ける
- [ ] 総容量超過（既存+追加）を計算して弾ける

**Policy**

**System**
- [ ] 25MB超のファイルでエラー表示され、Assetが作成されない
- [ ] 21件以上の一括投入でエラー表示され、Assetが作成されない
- [ ] 既存使用量がある状態で500MB超となる投入でエラー表示され、Assetが作成されない
