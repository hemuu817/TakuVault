# Issue #184: （48）Session統合画面のTurboキャッシュ復元修正

- URL: https://github.com/hemuu817/TakuVault/issues/184
- State: OPEN
- UpdatedAt: 2026-09-11T04:06:00Z
- Labels: 

## Body

## 目的

ADR-0019「Session一覧・Session詳細統合画面の表示・状態遷移・取得契約」で定義されたTurboキャッシュ復元契約を、現在のSession統合画面で成立させる。

現在のSession統合画面では、`turbo-cache-control=no-cache`によってページ全体のTurbo snapshot保存を無効化している。

本Issueでは、この`no-cache`依存を解消し、Turbo標準のキャッシュ・復元機構を利用した状態で、ADR-0019 D3 / D4 / D13に定められたURL・Session選択状態・一時状態・削除済みリソースに関する契約を成立させる。

`no-cache`の削除そのものではなく、ADR-0019に定められたTurboキャッシュ復元契約が実画面上で成立することを目的とする。

## 背景

Session統合画面では、過去にSession切替処理を独自JavaScriptで実装していた。

当時の実装では、Session切替中に以下をJavaScript側で管理していた。

- loading / error表示
- 実行中のfetch
- AbortController
- 手動の`history.replaceState`
- 手動のDOM置換
- 失敗時のロールバック

これらの途中状態がTurbo snapshotとして保存されることを防ぐため、コミット`3050d18`で以下が同時に導入された。

- Session統合画面への`turbo-cache-control=no-cache`
- `turbo:before-cache`による一時状態cleanup
- Stimulus Controllerの`disconnect`時のcleanup

一時状態をsnapshotへ残さないという目的自体はADR-0019 D13と一致する。

一方、現在利用しているTurboでは、`no-cache`指定ページはsnapshot保存対象にならないため、通常のsnapshot保存前に利用する`turbo:before-cache` cleanupも実行されない。

そのため、現行構成では一時状態の保存自体は防げるものの、ADR-0019 D13が前提とするTurboキャッシュからの復元経路も無効化されている。

その後、コミット`8978343`でSession切替処理はTurbo Frameへ委譲され、独自のfetch、AbortController、DOMParser、手動URL更新およびDOM置換は削除された。

現在の`session_switcher_controller.js`は主としてTurbo Frameのloading / error表示を制御する責務となっており、Session画面全体を`no-cache`とする当初の技術的前提は残っていない。

また、現在のSession / Scene削除はTurboが扱うunsafe form submissionとして実行されており、Turbo標準ではこの種のフォーム送信後にsnapshot cacheが無効化される。

そのため、削除済みSession / Sceneに対する独自snapshot管理は最初から導入せず、まずTurbo標準の挙動でADR-0019 D13の契約を満たせることを検証する。

## 前提 / 実装順

本Issueは以下の完了後に実装する。

1. #180「JavaScriptテスト基盤導入」
2. #181「既存System Specの責務再配置」

本Issueの実装は以下の順序を基本とする。

1. 現在の`no-cache`、loading / error表示、Turboイベント処理を確認する
2. `no-cache`を外した状態でTurbo restorationの実挙動を確認する
3. snapshot保存前に除去すべき一時表示を整理する
4. Session統合画面全体の`no-cache`依存を解消する
5. 必要な`turbo:before-cache` cleanupを追加または整理する
6. Turbo標準のrestorationだけでADR-0019 D3 / D4 / D13の契約を満たせるか確認する
7. 標準挙動だけで不足する場合に限り、URLを正本とした追加補正処理を検討する
8. Session / Scene削除後に、Turbo標準のcache invalidationで削除済みリソースが復元されないことを確認する
9. Request / JavaScript / System Specを必要範囲で更新する
10. 本Issueの変更に関連する回帰確認を行う

Turbo restoration時の追加JavaScript処理や独自snapshot無効化処理は、最初から導入を前提としない。

## スコープ

### 含む

#### Session統合画面のTurboキャッシュ設定

- Session統合画面に設定されている`turbo-cache-control=no-cache`を見直す
- ADR-0019の復元契約を成立させるため、画面全体の`no-cache`依存を解消する
- `no-cache`を削除したことだけを完了条件としない

#### snapshot保存前の一時状態cleanup

- `turbo:before-cache`でsnapshotへ残すべきでない一時表示を正常状態へ戻す
- 主な確認対象は以下とする
  - loading表示
  - 通信失敗時のerror表示・再試行導線
- 現在のSession切替実装に存在しない旧独自fetch用状態を再導入しない
- cleanupはsnapshotへ保存されるDOM状態の正常化を中心とする

#### Turbo restoration

ADR-0019 D3 / D4 / D13に基づき、以下の実画面上の復元を確認する。

- `/sessions`
- `/sessions/:id`
- Session切替後の履歴
- reload
- browser back / forward
- Turbo restoration

URLとcached DOMの状態が一致しない場合は、ADR-0019で定められたURL正本の契約を維持する。

具体的な補正実装は固定せず、Turbo標準挙動だけでは契約を満たせない場合に限り追加対応を検討する。

#### Session / Scene削除後の復元

- Session削除後に削除済みSessionが正常状態として復元されないことを確認する
- Scene削除後に削除済みSceneが正常状態として復元されないことを確認する
- Turbo標準のunsafe form submission後のcache invalidationを前提として検証する
- 標準挙動で契約を満たす場合、独自snapshot無効化処理を追加しない
- 不足が実証された場合に限り追加対策を検討する

#### テスト

ADR-0020および#181で定めた責務境界に従い、以下を必要範囲で追加または更新する。

- Request Spec
  - サーバー生成のSession選択状態
  - Turbo Frame構造
  - `no-cache`そのものを固定している既存期待値の見直し
- JavaScriptテスト
  - `turbo:before-cache`時のDOM cleanup
- System Spec
  - 実際のTurbo restoration
  - URL・Session選択状態・詳細表示の整合
  - 削除後の復元
  - 履歴操作との組み合わせ

JavaScript単体テストだけを、実画面上のTurbo restoration保証の代替にしない。
