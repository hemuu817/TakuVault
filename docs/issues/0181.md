# Issue #181: （47）既存System Specの責務再配置

- URL: https://github.com/hemuu817/TakuVault/issues/181
- State: OPEN
- UpdatedAt: 2026-09-09T16:05:16Z
- Labels: 

## Body

## 目的

ADR-0020「JSテスト移行とRSpecの債務境界」に基づき、既存RSpec System Specが担っている保証内容を棚卸しし、各保証を適切なテスト層へ再配置する。

本Issueでは、System Spec件数の削減自体を目的としない。

既存System Specそのものを負債とはみなさず、ADR-0020で定めた責務境界と一致していない保証を対象として再配置する。

移行先で同等保証が成立していることを確認した後、その保証に対応する既存System Specだけを縮小・削除する。

## 背景

現在のTakuVaultでは、JavaScript専用テスト基盤が存在しなかった経緯から、JavaScript Controllerの詳細挙動の一部もRSpec System Specで検証している。

先行Issue #180「（46）JavaScriptテスト基盤導入」では、以下を利用できる基盤を成立させる。

- Vitest + jsdom
- Vitest Browser Mode + Playwright

一方、#180では既存System Specの削除・縮小および本格的な責務再配置は行わない。

そのため本Issueでは、既存System Specの保証内容をファイル単位ではなく保証内容単位で確認し、既存Request Specおよび#180で成立したJavaScriptテストも再利用しながら、ADR-0020に従って責務を再配置する。

## 前提 / 実装順

本Issueは以下の完了後に実装する。

1. ADR-0020がAcceptedになっている
2. #180「（46）JavaScriptテスト基盤導入」が完了している
3. #180で定義したJavaScriptテストの正式実行経路が利用可能になっている

本Issueの実装は、以下の順序を基本とする。

1. 最新`main`の既存System Specを棚卸しする
2. 各exampleの保証内容を整理する
3. 既存Request Spec / jsdom / Browser Modeテストで同等保証が存在するか確認する
4. 不足する保証だけを移行先へ追加する
5. 既存System Specを残した状態で、移行先テストをローカル確認する
6. 既存System Specを残した状態で、移行先を含むCIを確認する
7. 同等保証が成立した部分だけ既存System Specを縮小・削除する
8. 最終状態で関連テストをローカル確認する
9. 最終状態でCIを確認する

モーダル実装は、本Issueの完了を待たず、#180完了後に進行可能とする。

RSpecのローカル / CI実行環境差の統一は、本Issueの前提または成果物には含めない。

## スコープ

### 含む

#### 既存System Specの棚卸し

実装開始時点の最新`main`に存在する`spec/system/`配下を棚卸しする。

現時点の対象は以下。

- `spec/system/assets_spec.rb`
- `spec/system/auth_spec.rb`
- `spec/system/sessions_spec.rb`
- `spec/system/uncategorized_assets_spec.rb`

各Specファイルを一括で移動・削除するのではなく、各exampleが実際に保証している内容を単位として確認する。

主要な再配置対象は以下とする。

- `spec/system/uncategorized_assets_spec.rb`
- `spec/system/sessions_spec.rb`

`assets_spec.rb`および`auth_spec.rb`についてもADR-0020との整合を確認するが、現在の責務配置が適切な保証を件数削減だけを理由に移動しない。

過去ブランチを遡ったSystem Specの再構成は行わない。

#### 保証対応表

各保証について、移行元と移行先を追跡できる保証対応表を作成する。

少なくとも以下を記録する。

| 項目内容 | |
| --- | --- |
| 移行元 | 現在のSystem Spec / example |
| 保証内容 | 現在保証している契約・挙動 |
| 配置先 | Request / jsdom / Browser Mode / System |
| 既存保証 | 既存テストですでに同等保証されているか |
| 追加先 | 不足する場合に追加したテスト |
| System残存保証 | System Specとして維持した保証 |
| ローカル確認 | 移行先の成功確認 |
| CI確認 | 移行先のCI確認 |
| 旧保証削減 | 縮小・削除したか |

保証対応表は、本Issueを実装するPR本文へ記載し、レビュー時に移行元・移行先・Systemへ残した保証を追跡できる状態にする。

#### 既存テストの再利用

保証を再配置する前に、既存のRequest Specおよび#180で追加されたJavaScriptテストを確認する。

既存テストですでに同等保証が成立している場合、新しいテストを重複して追加しない。

不足する保証だけを追加対象とする。

#### `uncategorized_assets_spec.rb`

`uncategorized_kind_controller`に関する、ブラウザ固有機能を必要としないJavaScript / DOM詳細を中心にVitest + jsdom側へ再配置する。

主な確認対象：

- kind選択に伴う選択制御
- checkboxの`disabled`
- 行の表示状態
- role候補の`hidden` / `disabled`
- 候補外になった選択中roleの解除
- 全選択解除後のUI状態
- 選択状態に応じた動的DOM順序
- Controllerが`turbo:before-cache`等のイベントを受けた際のDOM状態変更

初期HTML、サーバー側表示順、`data-*`等については既存Request Specを確認し、不足する保証だけをRequest Specへ追加する。

画面遷移またはブラウザバック後にも主要操作が成立することを実ブラウザ上の統合保証として維持する必要がある場合は、その保証をSystem Specへ残す。

#### `sessions_spec.rb`：サーバー側保証

`sessions_spec.rb`が担っている保証のうち、サーバー側の応答として確認可能なものについて既存Request Specを確認する。

主な確認対象：

- 認証・認可
- 他ユーザーSessionへの404
- HTML構造
- Turbo Frame
- `data-*`
- `aria-*`
- サーバー側で生成される選択状態
- CRUD後のHTTPレスポンスおよび遷移

既存Request Specで同等保証が成立している場合は再利用し、不足する場合のみ追加する。

#### `sessions_spec.rb`：`horizontal_scroll_controller`

`horizontal_scroll_controller`のブラウザ固有挙動について、#180で追加されたVitest Browser Mode + Playwrightテストを確認する。

主な確認対象：

- ArrowLeft / ArrowRight
- 対象外キー
- modifier付き操作
- 子要素由来イベント
- 横overflowの有無
- フォーカス
- 横スクロール

#180で同等保証が成立している場合は既存テストを再利用し、不足する保証だけを追加する。

#### `sessions_spec.rb`：主要統合導線

Rails / DB / Turbo / JavaScript / browserを横断する主要なSession操作については、System Spec側の保証を維持する。

主な確認対象：

- Session切替成功時のURL・選択表示・詳細表示
- Session切替中の直前正常状態の維持
- 通信失敗時の状態維持
- エラー表示と再試行
- 複数切替競合時の古い応答の扱い
- Turbo Frame異常応答時の処理
- Session切替とブラウザ履歴
- リロード後の状態
- ブラウザバック
- `target="_blank"`を含む通常リンク
- Session切替以外の通常画面遷移

異なる故障モードを保証しているexampleについては、System Spec件数を減らすためだけに一つへ統合しない。

#### Turboキャッシュ契約

責務再配置中に、ADR-0019で定義されているTurboキャッシュ上の要求と現在の実装・テストとの間に仕様差または保証欠落を発見した場合は、保証対応表へ記録する。

本Issueでは、その差異を責務再配置の一環として暗黙に仕様変更しない。

Turboキャッシュ方針そのものの変更が必要な場合は、本Issueの責務再配置とは分離して扱う。

#### 旧System Specの縮小・削除

既存System Specの一部を縮小・削除する場合は、先に移行先の同等保証を成立させる。

以下の状態で旧System Specを残したまま確認する。

- 移行先テストがローカルで成功する
- 移行先を含むCIが成功する

その後、同等保証が確認できた部分だけを縮小・削除し、最終状態でもローカルおよびCIを再確認する。

### 含まない

- JavaScriptテスト基盤の導入
- モーダル機能の実装
- ネイティブ`<dialog>`等のモーダル設計
- RSpec全体のリファクタリング
- 無関係なModel Spec / Policy Spec等の整理
- 過去ブランチを遡ったテスト再構成
- RSpecのローカル / CI実行環境差の統一
- System Spec件数削減だけを目的としたテスト削除
- 本番JavaScript配信方式の変更
- 製品仕様の変更
- JavaScript Controllerの再設計
- ADR-0019のTurboキャッシュ方針そのものの変更
- テスト責務再配置と無関係な本番コードのリファクタリング

## 受け入れ条件（Yes/No）

- 実装開始時点の`spec/system/`配下が全件棚卸しされている
- 各対象exampleの保証内容が保証内容単位で整理されている
- 各保証の配置先がADR-0020と一致している
- 移行元と移行先を保証対応表から追跡できる
- 保証対応表が実装PR本文へ記載されている
- 既存テストで同等保証されている場合は再利用されている
- 既存保証で充足している内容について不要な重複テストを追加していない
- サーバー側保証について既存Request Specが確認され、不足する場合だけ必要なテストが追加されている
- `uncategorized_kind_controller`について既存jsdomテストが確認され、不足する場合だけ必要なテストが追加されている
- `horizontal_scroll_controller`について既存Browser Modeテストが確認され、不足する場合だけ必要なテストが追加されている
- Rails / DB / Turbo / JavaScriptを横断する主要導線が必要なSystem Specとして維持されている
- Session切替と通常リンク / `_blank`との共存について必要な統合保証が維持されている
- Controller単体の`turbo:before-cache`等の検証だけを、実画面上のTurbo復元保証の代替として扱っていない
- 移行先のローカル確認前に対応する既存System Specを削除していない
- 移行先を含むCI成功前に対応する既存System Specを削除していない
- 旧System Spec縮小・削除後の最終状態でもローカルテストが成功している
- 旧System Spec縮小・削除後の最終状態でもCIが成功している
- 同じ詳細保証が複数のテスト層へ不必要に残っていない
- ADR-0019と現行実装・テストの仕様差を発見した場合、その内容が記録されている
- 本Issue内で製品仕様を暗黙に変更していない
- System Spec件数そのものを成果条件としていない

## 失敗ケース（最低3つ）

- 移行先で同等保証を確認する前に既存System Specを削除する
- JavaScript詳細を別テストへ移したことを理由に、Rails / DB / Turboを含むSystem保証まで削除する
- サーバー側契約をjsdomだけで保証する
- ブラウザ固有挙動をjsdomだけで保証する
- Browser ModeでController詳細を保証したことを理由に、主要なRails統合導線を削除する
- `turbo:before-cache`イベント単体のControllerテストだけで、実際のTurbo画面復元を保証済みと判断する
- 既存Request SpecまたはJavaScriptテストに同等保証があるにもかかわらず、同内容のテストを重複追加する
- 異なる故障モードをSystem Spec削減だけを目的として一つのexampleへまとめる
- Session切替後に通常リンクまたは`target="_blank"`リンクが壊れていることを見逃す
- 責務再配置の途中で製品仕様を変更する
- ADR-0019との仕様差を、本Issueのテスト変更だけで暗黙に解消したことにする
- System Spec件数が減らなかったことだけを理由にIssue未完了と判断する

## 最小テスト / 検証

### Request

- 既存System Specから抽出したサーバー側保証について既存Request Specを確認する
- HTTP / HTML / 認証・認可の不足保証がある場合は追加する
- Turbo Frame / `data-*` / `aria-*`等のサーバー生成契約について不足保証がある場合は追加する
- 既存Request Specで同等保証されている場合は重複追加しない

### jsdom

- `uncategorized_kind_controller`の既存テストを確認する
- kindに応じた選択制御を保証できる
- kindに応じたrole候補変更を保証できる
- `disabled` / `hidden` / class等のDOM状態を保証できる
- 動的DOM順序を保証できる
- 全選択解除時の状態を保証できる
- Controller単体で扱う必要がある`turbo:before-cache`等のイベント処理を保証できる
- 既存jsdomテストで同等保証されている場合は重複追加しない

### Browser Mode

- `horizontal_scroll_controller`の既存Browser Modeテストを確認する
- ArrowLeft / ArrowRightの既存挙動を保証できる
- 対象外キーの既存挙動を保証できる
- modifier付き操作の既存挙動を保証できる
- 子要素由来イベントの既存挙動を保証できる
- overflow有無による既存挙動を保証できる
- フォーカスおよび横スクロールの実ブラウザ挙動を必要範囲で保証できる
- 既存Browser Modeテストで同等保証されている場合は重複追加しない

### System

- Session切替成功時にURL・選択表示・詳細が一致する
- Session切替中に直前の正常状態を維持する
- Session切替失敗時に直前の正常状態を維持できる
- 切替失敗後に再試行できる
- 連続切替時に必要な競合時挙動を保証できる
- Turbo Frame異常応答時の既存統合挙動を保証できる
- Session切替によって不要なブラウザ履歴が追加されない
- リロード後にURLを基準とした状態を確認できる
- ブラウザバック時の主要導線を確認できる
- 通常リンクがSession切替用JavaScriptによって妨げられない
- `target="_blank"`リンクの既存動作が維持されている
- uncategorized画面について実画面遷移後の統合保証を残す必要がある場合、その保証が維持されている

### CI

- 既存System Specを残した状態で移行先テストを含むCIが成功する
- CI成功後に同等保証済みの旧System Specだけを縮小・削除する
- 旧System Spec縮小・削除後の最終状態でもCIが成功する
- Request / jsdom / Browser Mode / Systemのいずれかの関連テスト失敗を見逃さない

### 手動確認

- System Specとして残した主要導線について、必要な範囲で実ブラウザ上の動作を確認する
- Session切替後も通常リンクを利用できる
- Session画面の`target="_blank"`リンクが既存どおり動作する
- JavaScript詳細を別層へ移した後も、主要な利用者導線が変化していない
