# #22 Asset詳細：使用先（Where used）表示

## 目的（このIssueで達成する価値）
Asset詳細で、その素材の使用先（セッション／シーン／用途）を確認できるようにし、該当セッションへ遷移できるようにする。

## スコープ
**含む**
- Asset詳細ページに「使用先」セクションを追加し、当該Assetに紐づく usages を一覧表示する
- 表示項目：Session名 / Scene名 / 用途（= role enum の表示名）
- 表示順を定義する（例：Session名 → Scene.position → 用途 の昇順）
- usages=0 の場合は、空テーブルではなく最小限の状態表示を出す
  - 例：`使用先：未設定（未整理）`
  - 併せて「未整理一覧へ」導線を出す（未整理の実装自体は #19）
- 各行から Session詳細へ遷移できる（MVPは Session詳細リンクに統一）
- 認可：Asset を authorize し、表示対象 usages は「当該Asset」かつ「current_user 所有の session/scene」に限定する（fail-closed）
- N+1回避：usages の取得で session/scene を eager load する（includes/preload 等）

**含まない**
- Usage の作成・編集・削除（本Issueは表示のみ）
- 未整理フォルダ（usage=0 一覧）の実装（#19）
- 検索・絞り込みUI（別Issue）
- Scene詳細ページの新設（存在しない前提。表示のみ）

## 受け入れ条件（Yes/No）
- [ ] Asset詳細に「使用先」セクションが表示される（UIラベルに “Where used” を出さない）
- [ ] usages が 1件以上ある場合、Session名 / Scene名 / 用途 が一覧表示される
- [ ] 一覧の表示順が仕様通りである（定義したキーで安定）
- [ ] 一覧の各行から Session詳細へ遷移できる
- [ ] usages=0 の場合、`未設定（未整理）` の状態表示と「未整理一覧へ」導線が表示される
- [ ] 他ユーザーの Asset 詳細URL直打ちは閲覧できない（Punditで拒否）
- [ ] 表示される usage は「当該Asset」かつ「current_user の session/scene」のものに限定され、他ユーザー由来の混入がない（fail-closed）
- [ ] N+1 が発生しない（session/scene 参照でクエリが増えない）

## DoD（完了条件）
- [ ] controller/view が肥大化しない（取得ロジックは scope/query/presenter 等に寄せる）
- [ ] policy_scope / authorize の適用が確認できる（Asset起点の所有権）
- [ ] System spec で「usagesあり / usagesなし / 認可NG」を担保する

## 失敗ケース（最低3つ）
- [ ] 認可漏れで他ユーザーのAsset詳細が表示できてしまう
- [ ] usages 一覧に他ユーザーの session/scene を経由した usage が混入する（fail-closed 不備）
- [ ] session/scene 表示でN+1が発生し、件数増で表示が重くなる

## 最小テスト/検証
**Model/DB**
- [ ] （原則なし）※本Issue単独で新規制約は追加しない（必要なら別Issue/ADRへ）

**Policy**
- [ ] AssetPolicy#show?（または該当アクション）で所有権により拒否できる
- [ ] policy_scope(Asset) 起点で他人のAssetが参照できない

**System**
- [ ] 自分のAsset詳細で usages が表示される（Session/Scene/用途が見える、表示順が安定）
- [ ] 自分のAsset詳細で usages=0 のとき `未設定（未整理）` と未整理導線が表示される
- [ ] 他人のAsset詳細URL直打ちは拒否される（※拒否のHTTPステータスは全体方針に従う）
