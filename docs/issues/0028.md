## Body

## 目的（このIssueで達成する価値）
素材一覧で、表示名（display_name）または元ファイル名（ActiveStorage blob.filename）で素材を検索できるようにし、必要な素材を素早く見つけられるようにする。

## スコープ
**含む**
- 素材一覧（Assets#index）に検索入力（q）を追加する
- 検索対象
  - Asset.display_name
  - ActiveStorage blob.filename（left_joins(file_attachment: :blob) で参照）
- 検索仕様（固定）
  - policy_scope(Asset) 起点（認可漏れ防止）
  - PostgreSQL ILIKE（部分一致）
  - 複数語は空白（全角含む）で分割し **AND**（語ごとに絞る）
  - 1語内は `display_name OR filename`
  - 入力は正規化（strip/squish）し、空トークンは除外
  - ワイルドカード（%/_）はエスケープ（sanitize_sql_like 等）
  - 負荷防御（MVP最小）：q 最大長=100、最大トークン数=5（超過は切り詰め）
- デフォルト順序を固定（検索あり/なし共通）
  - created_at desc（例）
- 実装は Query Object に集約する（Controller直書き禁止）

**含まない**
- 絞り込み（kind/role/session）やソートUI（別Issue）
- Usage JOIN を伴う検索（distinct 等が絡むものは別Issue）
- 高度な検索（OR指定、完全一致、正規表現）
- 検索高速化（pg_trgm 等）はMVP外（必要ならADR/別Issue）

## 受け入れ条件（Yes/No）
- [ ] 素材一覧に検索入力があり、q で検索できる
- [ ] display_name または filename に一致する素材がヒットする（ILIKE部分一致）
- [ ] 複数語検索はANDで絞られる（各語がヒットしない素材は除外）
- [ ] policy_scope 起点であり、他ユーザーの素材は検索結果に出ない
- [ ] q が空/未指定なら通常の一覧が表示される
- [ ] %/_ を含む入力でもSQLエラーにならず、安全に検索できる（エスケープされる）
- [ ] 検索あり/なし双方で、結果順序が固定されている（created_at desc）

## DoD（完了条件）
- [ ] Query Object（例：AssetSearchQuery）に「正規化/分割/エスケープ/where生成」を集約している
- [ ] controller にSQLを直書きしない
- [ ] System spec で「ヒット」「複数語AND」「認可（他人が出ない）」「順序固定」を担保する

## 失敗ケース（最低3つ）
- [ ] policy_scope を使わず、他ユーザーの素材が検索結果に混入する
- [ ] 複数語がOR扱いになり、意図より広くヒットして参照速度が落ちる
- [ ] %/_ を含む入力で意図しない全件ヒット、またはSQLエラーになる

## 最小テスト/検証
**Model/DB**
- [ ] Query Object が display_name/blob.filename を ILIKE で絞れる
- [ ] 複数語入力でAND条件になる
- [ ] created_at desc の順序が固定される

**Policy**
- [ ] policy_scope(Asset) 起点で他人の素材が検索結果に出ない

**System**
- [ ] 自分の素材が q でヒットする（display_name/filename両方）
- [ ] 複数語ANDで意図通りに絞られる
- [ ] 他人の素材は検索結果に出ない
- [ ] 期待順序で表示される（created_at desc）
