## Body

## 目的（このIssueで達成する価値）
Usage（asset + session + scene + role）の割当ルールを **ADR-0006 に一本化**し、後続実装（未整理一括割当/Usage作成/Where used表示/検索絞り込み）が仕様ブレなく進む状態にする。

## スコープ
**含む**
- ADR-0006 に「割当ルール（正規導線/一括割当単位/重複扱い/所有権/不整合/選択保持）」を記載して正本化
- 後続Issueが参照できる形で、成功例/失敗例を最小セットで整理

**含まない**
- UI実装（未整理ページ、チェックボックス、Turbo、フォーム）
- 自動推定（role推定等）
- 検索/ソート/フィルタの実装（Epic E側）

## 受け入れ条件（Yes/No）
- [ ] ADR-0006 が作成され、以下が**決定事項として固定**されている
  - [ ] 正規導線：未整理（Usage0）で複数選択→一括割当（Secondary：Asset詳細で保守）
  - [ ] 一括割当単位：`session + scene + role` を選択Assetへ適用
  - [ ] 重複：**全ロールバックしない**（冪等/スキップ等、方針を明文化）
  - [ ] 所有権混在：fail-closed（即失敗）
  - [ ] session–scene不整合：UIで予防＋DBで拒否（複合FK前提）
  - [ ] 選択状態保持：要件として固定
- [ ] 成功例3つ＋失敗例3つが ADR-0006 に記載され、後続IssueのACへ転記できる
- [ ] 本Issue本文に決定事項の再掲がなく、ADR参照に集約されている（保守性）

## DoD（完了条件）
- [ ] ADR-0006 がリポジトリに追加され、Epic D/Eの関連Issueから参照されている
- [ ] 後続Issue（未整理導線/Usage作成/Where used表示/検索絞り込み）に Relates to: ADR-0006 を付ける準備ができている

## 失敗ケース（最低3つ）
- [ ] 重複（同一 asset/session/scene/role）が混ざった一括割当で、全体ロールバックして作業が止まる
- [ ] 他人のasset/session/scene混在が検知できず、作成される（情報漏えい/破壊）
- [ ] 別sessionのsceneでUsageが作れてしまう（整合性崩壊）

## 最小テスト/検証（このSpikeでは「観点定義」まで）
**Model/DB（前提の確認）**
- [ ] UNIQUE(asset_id, session_id, scene_id, role)
- [ ] 複合FK：usages(session_id, scene_id) -> scenes(session_id, id)
- [ ] role NOT NULL / scene_id NOT NULL

**Policy（前提の確認）**
- [ ] Usage作成は混在不可（asset_ids / session / scene を policy_scope/authorize で拘束）

**System（観点定義）**
- [ ] 未整理で一括割当しても、重複が混ざった場合に“全体が止まらない”方針になっている（ADRで明文化）
