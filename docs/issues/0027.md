## Body

## 目的
素材が増えても探せる状態（検索/絞り込み/ソート）を提供し、MVP勝利条件の「一覧で参照できる」を満たす。  
所有権（policy_scope）を前提に、JOINを伴う条件でも重複表示やN+1を起こさない。

---

## 前提（固定）
- DBダンプは **structure.sql** を採用（DB制約/Indexを正確に反映する）
- `assets.original_filename` を保持して検索する（ActiveStorageの `blobs.filename` へJOINして検索しない）
  - 取得元：アップロード時に `file.blob.filename.to_s` を `assets.original_filename` にコピー（Epic D側で実装）
- 検索の起点は常に **`policy_scope(Asset)`**（情報漏えい防止）
- Usage JOIN を伴う条件では **`distinct`** で重複排除する（固定）

---

## DoD（完了条件）

### 検索（キーワード）
- [ ] Assetを `display_name` / `original_filename` で検索できる
- [ ] 検索仕様が固定されている（実装ブレ防止）
  - [ ] 部分一致（`ILIKE '%term%'`）
  - [ ] 大小文字無視（`ILIKE`）
  - [ ] 複数語（スペース区切り）は **AND**（各語がどちらかのカラムに一致すればOK）
  - [ ] 前後空白はトリム、連続空白は区切り扱い
  - [ ] LIKEワイルドカードは `sanitize_sql_like` で無害化
- [ ] 空クエリは全件（policy_scope内）

### 絞り込み（MVP範囲）
- [ ] 絞り込みができる（MVP：`tag` / `role` / `session` / `kind`）
- [ ] 絞り込みの意味が固定されている（仕様ブレ防止）
  - [ ] `tag`：指定タグを持つAssetのみ
  - [ ] `role`：指定roleのUsageを1件以上持つAssetのみ
  - [ ] `session`：指定sessionのUsageを1件以上持つAssetのみ
  - [ ] `kind`：Asset.kind一致のみ
  - [ ] 絞り込み無しの場合は Usage 0（未整理）も含む（未整理専用導線は別Issue）

### ソート
- [ ] ソートを切替できる（最低限：`newest` / `oldest`）
- [ ] ソートは `assets.created_at` を基準に固定（JOINでブレない）

### 重複排除 / 性能
- [ ] Usage JOIN を伴う場合は `distinct` 等でAssetの重複表示を排除
- [ ] N+1を回避（必要に応じて `includes`）
  - [ ] 一覧で表示する関連を前提に `includes` を固定（下記「表示項目」参照）
- [ ] 最低限のインデックスが存在する（structure.sqlに反映済み）

### 認可
- [ ] 検索・絞り込み・ソートの全条件で **policy_scope(Asset)** を起点にし、他人のAssetが混入しない

## スコープ

### 含む
- 検索フォーム（キーワード）
- 絞り込み（tag/role/session/kind：MVP範囲）
- ソート切替（newest/oldest）
- 重複排除（distinct）・N+1回避（includes）
- DB index（最低限）

### 含まない
- 高度な全文検索（Elasticsearch等）
- 保存検索、レコメンド
- 複雑なランキング/スコアリング
- 検索結果のハイライト

## DB要件（structure.sql に反映）
### columns
- [ ] assets.original_filename（text推奨）
- [ ] assets.display_name（既存）
- [ ] assets.kind（Epic Dで追加済み想定）

### indexes（最低限）
- [ ] `index_assets_on_user_id_and_created_at`（一覧/ソート）
- [ ] `index_assets_on_user_id_and_display_name`（検索の最低限）
- [ ] `index_assets_on_user_id_and_original_filename`（検索の最低限）

## 実装方針（固定）
- 検索の起点は `policy_scope(Asset)`（これを崩さない）
- 検索語は `split(/\s+/)` で分割し、各termをANDで積む
- LIKEは `sanitize_sql_like` を使用し、`%`/`_` を無害化
- role/session/tag のフィルタは必要時のみJOINし、Usage JOIN時は `distinct` を必ず付与
- ソートは `assets.created_at` のみ（JOINに引っ張られない）

## 最小テスト/検証（MVP最小・CI安定重視）

### System（最低3ケース：主要導線）
- [ ] キーワード検索：display_name でヒットする
- [ ] キーワード検索：original_filename でヒットする
- [ ] 絞り込み＋重複排除：同一AssetにUsageが複数あっても一覧に1回だけ表示される（role or session フィルタで確認）
- [ ] ソート切替：newest/oldest で並びが変わる

### Request / Query（自動で担保）
- [ ] policy_scope起点：他人のAssetが結果に混入しない
- [ ] 複数語AND：2語指定で両方を満たすAssetのみ返る
- [ ] sanitize：`%` や `_` を含む語でも例外が起きず、クエリが破綻しない
- [ ] distinct：Usage JOIN時に `assets.id` の重複が発生しない

※ 「ログでN+1確認」は補助（手動）に降格。CIでは結果の正しさ（重複なし/漏えいなし）を優先。
