### 本サービスの概要（700文字以内）
TakuVaultは、TRPGセッションツールで使用する背景・カットイン・BGM等の素材をクラウド上に保存し、「どのセッション／どのシーン／どの用途（role）で使った素材か（Where used）」を記録して逆引きできる素材保管庫です。
KP / GMがセッション準備・振り返りを行う際に発生しがちな「良かった素材を再利用したいのに、いつどこで使ったかを忘れてしまって再利用できない」という課題を解決します。
MVPではCocofoliaのみを対象とし、部屋URL（room_url）を保存してアプリから該当セッションへ遷移できるようにします（同期/API連携は行いません）。
素材はドラッグ&ドロップで一括アップロードし、リネーム・タグ付け・検索（ファイル名/表示名）・絞り込み・ソートを提供します。さらに、素材詳細から「どのセッション/シーン/用途（role）で使ったか」をWhere usedとして確認でき、必要な素材を素早く再発見できるようにします。

### MVPで実装する予定の機能
- 認証：ユーザー登録 / ログイン / ログアウト（Devise）
- 認可：所有者のみアクセス可能（Pundit等で policy_scope / authorize を全CRUDで徹底。URL直打ちも遮断）
- 対象ツール：Cocofolia のみ
  - ルーム連携は同期/API連携は行わず、部屋URL（room_url）を保存して参照/遷移できる形に留める
- セッション/シーン管理
  - Session / Scene を管理し、Session作成時に default_scene を自動作成（default_scene は削除不可）
- 素材管理（Asset）
  - 1ファイル = 1Asset（ActiveStorage）
  - 複数ファイル一括アップロード（ドラッグ&ドロップ必須 + 複数選択フォールバック）
  - リネーム（display_name）
- Where used（Usage）
  - Assetが「どのSession / どのScene / どのRoleで使われたか」を記録して逆引きできる
  - Sceneは必須（未割当は default_scene に紐付けて管理）
  - role は許容値固定（例：background / cutin / bgm / other）
  - 同一 asset×session×scene×role の重複登録は不可
- タグ
  - DBは多対多（tags / asset_tags）。UIはMVPでは単数運用でも可
- 検索/絞り込み/ソート
  - display_name / original_filename（ActiveStorage blob.filename）で検索
  - kind / role / session 等で絞り込み、ソート対応（検索はRansack利用予定）
- アップロード安全性
  - Content-Type/拡張子、サイズ上限をサーバ側で検証（クライアント依存にしない）

- id : bigint / PK / タグ識別子

- created_at : timestamp / 作成日時
- updated_at : timestamp / 更新日時

asset_tags（素材×タグ：中間テーブル）
- id : bigint / PK / 紐付け識別子

- tag_id : bigint / FK → tags.id / 付与タグ

- byte_size : bigint / ファイルサイズ
- service_name : varchar / 使用ストレージ識別子（例：R2等）

- created_at : timestamp / 作成日時

### ER図補足：整合性・運用ルール

- Where used整合：usages.session_id は冗長だが、scene の所属 session と一致を DBの複合FKで保証するため保持。
FK usages(session_id, scene_id) REFERENCES scenes(session_id, id)（前提：UNIQUE(scenes.session_id, scenes.id) **※ER図/DBML側に定義済み**）

- default_scene：usages.scene_id NOT NULL の受け皿。最大1件はDB（部分ユニーク）、必ず1件はアプリ（作成時生成）。default_scene は直接削除不可（session削除に伴うCASCADEは許容）。
UNIQUE (session_id) WHERE is_default = true / UNIQUE(session_id, position)

- 所有権（認可）：全CRUDで policy_scope/authorize。親を current_user スコープで確定してから子を操作（ID直信用しない）。

### DB整合性

- 重複禁止：UNIQUE(asset_id, session_id, scene_id, role)
- scenes.position：max+1、衝突時リトライ（アプリ）
- tags：UNIQUE(user_id, name)
- asset_tags：UNIQUE(asset_id, tag_id)（多対多の重複禁止）

### 削除ポリシー（DB寄せ：原則ON DELETE CASCADE）

| 親 | 子 | 方針 |
|---|---|---|
| sessions | scenes | DB: ON DELETE CASCADE |
| scenes | usages | DB: ON DELETE CASCADE（複合FK経由） |
| assets | usages | DB: ON DELETE CASCADE |
| tags | asset_tags | DB: ON DELETE CASCADE |
| assets | asset_tags | DB: ON DELETE CASCADE |
| sessions | assets | 削除しない（素材は再利用前提で残す） |

補足：
- `sessions -> usages` の直接CASCADEは張らず、`sessions -> scenes -> usages` の経路に統一（削除経路の二重化を回避）。
- Asset削除は Usage を先に削除し、**その後** 添付は ActiveStorage の `purge_later` で後追い削除（整合順序を固定）。


### セキュリティ
- room_url：http/httpsのみ（host allowlistなし）＋ target="_blank" rel="noopener noreferrer"
- uploads：Content-Type/拡張子/サイズをサーバ側で拒否、Direct Uploadは使わず multipart 統一
- role/kind：許容値固定＋NOT NULL
- 検索・絞り込みで usages をJOINする場合は distinct で重複排除（JOINで重複し得るため）。

 
### ActiveStorage
- 添付はActiveStorage（polymorphicのため厳密FK不可）
- has_one_attached :file により 1 Asset = 1 file をアプリで担保
- filenameは active_storage_blobs.filename を検索対象に含める
- URL生成（署名URL含む）は認可済み Asset からのみ行う
