# Epic I : Rails最新版への移行

## 目的（このEpicで達成する価値）
TakuVaultを現在のRails 7.2.3系からRails 8系へ段階的に移行し、既存機能・CI・preview環境を壊さずに、継続保守できる状態へ更新する。

特に、単にGemfile上のRailsバージョンを上げるのではなく、以下を確認しながら段階的に進める。

- Rails 8.0系で既存アプリが動作すること
- Rails 8.1系への移行可否と影響範囲を確認すること
- framework defaults の更新判断を、Rails本体更新とは分離して扱うこと
- CI / Brakeman / preview環境 / ActiveStorage / Solid Queue / Render運用を壊さないこと

このEpicは、機能追加ではなく **基盤保守・フレームワーク更新** を扱う。

---

## 前提（固定）
- 既存のMVP機能を壊さないことを最優先する
- Rails移行は Phase 0 / Phase 1 / Deferred の既存機能ロードマップには混ぜない
- 親Issueではコード変更を行わず、実作業はsub issueに分割する
- `rails app:update` 等の自動更新系コマンドは、差分確認なしに反映しない
- framework defaults の更新は、Rails本体更新とは別論点として扱う
- 本番相当確認は preview 環境（Render / `RAILS_ENV=production`）で行う
- ActiveStorage / Cloudflare R2 / Solid Queue / Render Web+Worker構成への影響を必ず確認する

## 進め方（段階移行 / 打ち切り条件）
- Gate1：Rails 8.0でローカル起動・主要導線確認ができるまで、Rails 8.1へ進まない
- Gate2：Rails 8.1でローカル起動・主要導線確認ができるまで、framework defaults更新判断へ進まない
- Gate3：framework defaults は自動反映せず、差分確認後に適用 / 保留を判断する
- Gate4：previewで主要導線が壊れる場合、原因をRails本体更新 / framework defaults / gem依存 / Render設定に切り分ける
- Gate5：既存MVP機能を壊す変更が必要になった場合、このEpic内で無理に修正せず、別Issue化を検討する

---

## 注意点
- このEpicは「Rails最新版へ移行すること」が目的であり、ついでの設計改善や画面改善は扱わない
- framework defaults は、Railsバージョン更新とは別のリスクを持つため、同時に雑に反映しない
- `rails app:update` 等で生成される差分は、必ず内容を確認してから採用する
- 破壊的操作は禁止する
  - DB drop
  - 強制push
  - 強制rebase
  - 無条件削除
- 既存CIが失敗した場合は、Rails移行による失敗か、既存問題の顕在化かを切り分ける
