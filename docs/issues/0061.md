## スコープ

### 含む
- Model/DB：
  - 添付必須
  - サイズ上限
  - Content-Type / 拡張子制限（サーバ側）
  - DB制約（P0で必須のものを列挙）
- Policy（Pundit等）：
  - 所有権（policy_scope / authorize を全CRUDで徹底）
  - URL直打ち（他人ID）を防ぐ（挙動を方式固定：404 or 403）
- System（最小・短い導線に限定）：
  - 複数ファイル投入 → 複数Asset作成（CI安定重視）
  - Usage付与 → Where used 表示
  - 削除整合性（Asset削除でUsage/添付が破綻しない）
- 手動QA：
  - D&D確認
  - ブラウザ依存のフォールバック（複数選択）
  - エラー表示（不正アップロード時）

### 含まない
- 高度な性能テスト/負荷試験
- P1以降の機能（検索/絞り込み、タグ等）を前提にしたSystemテスト

## 最小テスト方針（方式固定）
### Model/DBで担保するもの（例）
- 添付必須（Assetはファイル無しで作れない）
- サイズ上限（1ファイル）
- Content-Type / 拡張子制限（サーバ側）
- DB制約（P0必須を列挙）
  - usages：UNIQUE(asset_id, session_id, scene_id, role)
  - scenes：default_scene の一意（session単位）
  - scenes：UNIQUE(session_id, position)
  - （該当する場合）usages の複合FK（session_id, scene_id）
  - ActiveStorage関連の整合（削除時の破綻を出さない）

### Policyで担保するもの（方式固定）
- index は policy_scope を使用
- show/create/update/destroy は authorize を必須化
- URL直打ち（他人ID）時の挙動を固定：**404**（推奨） or 403（どちらかに統一）
- 対象リソース（最低限）：
  - Session / Scene / Asset / Usage（＋Tag/AssetTagはP1扱いなら除外）

### Systemで担保するもの（最小・分割）
※長大シナリオ禁止。以下の3本に固定する。

1. `system/assets_upload_spec`
   - ログイン → 複数ファイル選択でアップロード → Assetがファイル数分作成される
2. `system/usages_spec`
   - ログイン → Asset作成（またはfixture） → Usage付与 → Asset詳細でWhere usedが表示される
3. `system/delete_integrity_spec`
   - ログイン → Asset+Usage作成 → Asset削除 → 画面/DBが破綻しない（必要なら添付も確認）
