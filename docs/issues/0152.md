## Body

# Rails 8.x framework defaults 段階適用

## 目的
Rails 8.1系で既存MVP機能の動作確認が完了している状態を前提に、Rails 8.x framework defaults を段階的に検証し、TakuVault の既存MVP機能を壊さずに `config.load_defaults 8.1` へ上げられるか判断する。

本Issueでは、Rails本体のバージョン更新ではなく、framework defaults の採用可否判断を目的とする。

`config.load_defaults 8.1` への到達は必須完了条件にしない。問題がある設定は旧挙動へ明示固定し、理由を記録する。

## 背景
TakuVaultのRails 8系移行は、以下の3段階に分けて進める。

1. Rails 7.2.3 → Rails 8.0系 動作確認
2. Rails 8.0系 → Rails 8.1系 段階移行
3. Rails 8.x framework defaults 段階適用

Rails本体更新と `config.load_defaults` 更新を同時に行うと、不具合発生時に「Rails本体更新の影響」なのか「framework defaults変更の影響」なのかを切り分けにくくなる。

そのため、前段Issueでは `config.load_defaults 7.2` を維持したままRails本体のみを8.1系へ移行し、本IssueでRails 8.x framework defaultsを段階的に検証する。

前提Issue「Rails 8.0系 → Rails 8.1系 段階移行」が green でない場合、本Issueは BLOCKED とする。

## 決定事項
- 前提Issueが green でない場合、本Issueは BLOCKED とする
- 本IssueではRails本体のバージョン更新を扱わない
- 検証順序は「Rails 8.0由来defaults → Rails 8.1由来defaults」とする
- Rails 8.0由来defaultsの検証は、Rails 8.0へ戻す意味ではない
- `config.load_defaults 8.1` への到達は必須完了条件にしない
- 各defaults候補は「採用 / 旧挙動固定 / 保留」で記録する
- 問題がある設定は旧挙動へ明示固定してよい
- `bin/rails app:update` は必須タスクにしない
- `bin/rails app:update` を使う場合も、差分調査に限定し、自動上書き・一括採用は行わない
- RSpecは `bin/rspec` を使用する
- 原則として新規ADRは作成しない
- 既存ADRの意味が変わる場合のみ、ADR改訂または新ADRを別途検討する

## Verification
ローカルでは、Docker Compose環境を前提に最低限以下を確認する。

```bash
docker compose exec web bin/rails db:prepare
docker compose exec web bin/rails db:migrate
docker compose exec web bin/rails routes
docker compose exec web bin/rails tailwindcss:build
docker compose exec web bin/rspec
```

ホスト側でRailsを直接実行できる環境が整っている場合のみ、上記の `docker compose exec web` を省略してよい。

production相当の assets:precompile を確認する。

```bash
RAILS_ENV=production SECRET_KEY_BASE_DUMMY=1 APP_HOST=localhost:3000 bundle exec rails assets:precompile
```

production相当boot / env fail-fast は最低限以下を確認する。

- `APP_HOST` 不足時にfail-fastする
- R2系環境変数不足時にfail-fastする
- 必須envを揃えた場合、production相当bootが通る

ローカル主要導線では最低限、以下を確認する。

- ログイン
- Assetアップロード
- Asset一覧
- Asset詳細
- Session詳細
- Where used表示
- Usage作成 / 更新
- Asset削除
- 削除後の参照不能
- 不許可形式・サイズ超過の拒否
- 他人のAsset URL直打ちが通らない

framework defaults 由来の回帰確認として最低限、以下を確認する。

- redirectを伴う主要導線が例外なく動作する
- order依存finderの曖昧な利用がない、または明示orderで補正されている
- 主要ERB画面とTailwind buildが維持されている
- previewでWeb / Workerが継続起動し、`purge_later` が滞留しない

preview環境では最低限、以下を確認する。

- Web Service が起動する
- Worker Service が起動する
- アップロード → 一覧 → 詳細 → Session詳細 → Where used → 削除 → 再参照不能が成立する
- 再デプロイ後もR2上の添付を参照できる
- `purge_later` / `analyze` / `variant(transform)` が滞留しない
- 不許可形式・サイズ超過がサーバ側で拒否される
- 他人のAsset URL直打ちが通らない

## deprecation warning の扱い
- framework defaults候補と関係するものは本Issueで整理する
- Rails本体更新やgem更新に関係するものは別Issue候補にする
- 判断不能なものは記録のみ残す
- 動作に影響しないwarningを、本Issue内で無理にすべて解消しない
