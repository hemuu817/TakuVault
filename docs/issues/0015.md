# Issue #15: (8) Scene CRUD+position

## Body

## 目的
- セッション配下にシーンを作成/参照/更新/削除できる（default_scene常設・削除不可）
- Usageの前提（`scene_id NOT NULL`）を満たし、Where used の土台となる整合性を確立する

## DoD
- [ ] Scene CRUD が動作し、`policy_scope/authorize` で所有権が徹底されている（URL直打ち含む）
- [ ] default_scene は各Sessionに必ず1つ存在し、削除できない（`position=1` を占有）
- [ ] default_scene は不変（`is_default=true` の降格不可 / `position=1` 変更不可）
- [ ] user作成Sceneは `position=2` から採番され、`UNIQUE(session_id, position)` を満たす（競合時リトライ）
- [ ] DB整合性（structure.sql前提）
  - scenes の NOT NULL/DEFAULT が揃っている（`is_default/position/name/session_id`）
  - default_scene一意（部分UNIQUE）・position一意（UNIQUE）・必要FKが揃っている（ON DELETE CASCADE）
  - Usageの複合FK前提が成立している（`scene_id NOT NULL`）
- [ ] 削除整合性は **DB CASCADE** で統一されている
  - Session削除 → Scenes/Usages削除（Assetsは残る）
  - Scene削除（default以外）→ Usages削除（Assetsは残る）
- [ ] 最小テスト（Model/Policy/System）が揃っている（不正アクセス/削除不可/採番競合/422・404の使い分け含む）

## スコープ
### 含む
- Scene：index/new/create/edit/update/destroy（Session配下のネスト前提）
- default_scene（常設）
  - Session作成時に自動生成される前提（※生成自体は(7)で実施）
  - 本Issueでは「削除不可」「不変」「一意」「position=1占有」を保証する
- position採番（ユーザー作成Scene）
  - `position = max(position) + 1`（最小2）
  - `UNIQUE(session_id, position)` 衝突時は再計算してリトライ（上限回数あり）
- DB制約（列挙・DB CASCADE前提）
  - `scenes.session_id -> sessions.id ON DELETE CASCADE`
  - `scenes`: `is_default boolean NOT NULL DEFAULT false`
  - `scenes`: `position integer NOT NULL`
  - `scenes`: `name varchar NOT NULL`
  - `scenes`: `UNIQUE(session_id, position)`
  - `scenes`: `UNIQUE(session_id) WHERE is_default=true`（default_scene一意）
  - `scenes`: `UNIQUE(session_id, id)`（Usage複合FKの前提）
  - `usages`: `(session_id, scene_id) -> scenes(session_id, id) ON DELETE CASCADE`（複合FK）
  - （必要なら）`usages.session_id -> sessions.id ON DELETE CASCADE`（存在する場合は明示）
- 削除整合性
  - default以外のScene削除 → Usages削除（DB CASCADE）

### 含まない
- Session作成（default_scene生成）は(7)の責務（本Issueは整合性とCRUD中心）
- Scene並び替えUI（ドラッグ等の高度機能）
- Sceneテンプレ/コピー、bulk編集

## 受け入れ条件（Yes/No）
- [ ] Session作成済みの状態で、default_scene が必ず1つ存在する
- [ ] default_scene は削除できない
  - [ ] UI上で削除導線が表示されない
  - [ ] destroy要求は **422** で失敗し、エラーメッセージが表示される（500にならない）
- [ ] default_scene は不変（更新で `is_default/position` を変更できない）
- [ ] Sceneを作成でき、position が 2 以上で採番される（defaultは1のまま）
- [ ] 同一Session内で position が重複しない（競合時はリトライして作成でき、500にならない）
- [ ] 他人のSession/Sceneにアクセスすると **404** になる（方式固定）
- [ ] default以外のSceneを削除すると、そのScene配下のUsageが削除される（Assetsは残る）

## 実装メモ（方式固定）
- 取得手順（ネスト前提で事故防止）
  - `@session = policy_scope(Session).find(params[:session_id])`
  - `@scene = @session.scenes.find(params[:id])`
  - `authorize @scene`
- default_scene不変
  - `is_default=true` の降格禁止（updateで弾く）
  - `position=1` の変更禁止（updateで弾く）
  - 非defaultは `is_default=false` 固定（trueに変更させない）
- position採番（競合リトライ）
  - `position = [2, @session.scenes.maximum(:position).to_i + 1].max`
  - `ActiveRecord::RecordNotUnique` を捕捉して再計算（例：最大5回）
- ステータスの使い分け
  - 他人ID直打ち：404（所有権秘匿）
  - default_scene削除禁止：422（ルール違反として説明しやすい）

## 最小テスト/検証
- Model/DB
  - [ ] `UNIQUE(session_id, position)` が効く
  - [ ] `UNIQUE(session_id) WHERE is_default=true` が効く
  - [ ] NOT NULL/DEFAULT（is_default/position/name/session_id）が効く
  - [ ] position採番：max+1（最小2）、競合時リトライで落ちない
- Policy
  - [ ] policy_scopeで他人のSceneが一覧に出ない
  - [ ] show/destroyで他人ID直打ちが404
- System（短い導線1本で可）
  - [ ] Scene作成→positionが2以上
  - [ ] default_scene削除が422で失敗し、エラー表示される
  - [ ] default以外Scene削除→配下Usageが消える（最小のUsageを作って検証）
