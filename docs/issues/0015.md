## Body

## 目的（このIssueで達成する価値）
Session配下のSceneを整合性を崩さずCRUDでき、default_scene（position=1）が常に存在する状態と position 管理を保証する。

## スコープ
**含む**
- Scene CRUD（一覧/作成/更新/削除）
- default_scene（position=1）の不変条件（削除不可・移動不可）
- position 採番：`max(position) + 1`（ユーザー作成は 2 から）
- position 一意性：`UNIQUE(session_id, position)` を前提に、衝突時リトライ（unique_violation捕捉→再計算→再試行）
- 認可（policy_scope/authorize）前提のCRUD

**含まない**
- ドラッグ&ドロップによる並び替えUI（MVP外）
- 任意position指定の挿入（MVP外）
- default_scene の「別Sceneへの差し替え」（MVP外）

## 受け入れ条件（Yes/No）
- [ ] 各Sessionに default_scene（position=1）が常に1つ存在する
- [ ] default_scene（position=1）は削除できない（UI非表示 + URL直打ちでも不可）
- [ ] ユーザー作成Sceneは position=2 から採番される（2,3,4...）
- [ ] 同一Session内で position は重複しない（DB制約で拒否）
- [ ] 衝突時は再計算してリトライし、作成が成立する（または明確に失敗する）

## DoD（完了条件）
- [ ] policy_scope/authorize の適用漏れがない（index/show/new/create/edit/update/destroy）
- [ ] default_scene（position=1）の不変条件が controller/model の両面で防御される
- [ ] 採番が `max+1` で、unique_violation 時に再試行する
- [ ] DB制約が migration で実装済み（付録B）
- [ ] 最小テスト/検証が通る（下記）

## 失敗ケース（最低3つ）
- [ ] position=1 のSceneを削除しようとして弾かれる（URL直打ち含む）
- [ ] position=1 のSceneの position を変更しようとして弾かれる（空席化防止）
- [ ] Scene作成が同時実行で position 重複し、例外で落ちる（＝リトライで吸収 or 明確に失敗させる）

## 最小テスト/検証
**Model/DB**
- [ ] `UNIQUE(session_id, position)` が効く
- [ ] default_scene（position=1）が存在しない状態を作れない（少なくとも作成フローでは発生しない）

**Policy**
- [ ] 他人のSession/Sceneにアクセス不可

**System**
- [ ] Session作成 → default_scene（position=1）を確認
- [ ] Scene追加 → position が 2,3,... と採番される
- [ ] default_scene削除（URL直打ち）失敗を確認
