## Body

## 目的（このEpicで達成する価値）
MVP開発を止めずに進めるための土台（開発環境・CI・stagingデプロイ）を整備し、以降のIssueが**安定して実装/検証できる状態**にする。  
特に、不変条件（所有権認可 / DB整合性 / アップロード安全性）を**“方針で固定”**し、逸脱を早期検知できるガードレールを用意する。

## DoD（Epic完了条件）
- [ ] **ローカル開発が再現可能**（README + `bin/setup` 相当で起動できる）
- [ ] **CIが最低限動作**（Rubocop + RSpec が完走 / PostgreSQL込み）
- [ ] **stagingにデプロイできる**（Render(Docker) / DB接続 / migrate / トップ表示）
- [ ] **ヘルスチェックが通る**（`GET /up` 等が200。stagingの稼働確認が明確）
- [ ] **認可方式が固定され、逸脱が検知できる**
  - [ ] Pundit導入、`ApplicationPolicy` 雛形
  - [ ] `verify_authorized` / `verify_policy_scoped` を原則ON（必要箇所は明示的にskip）
  - [ ] Policy spec 最小1本（所有権NGが落ちる）
- [ ] **ActiveStorageが dev / CI / staging で動作**（添付→参照の最短導線が1つ通る）
  - [ ] stagingはディスク運用でも可（永続しない前提を明記。永続はEpic XでR2）
- [ ] **テスト方針が固定**（CIで担保する範囲 / 手動QA範囲が明文化されている）
- [ ] **10時間タイムボックス内で完了**（未完要素は次Epicへ持ち越さず、Issue分割で管理）

## スコープ
### 含む
- Docker Compose による開発環境統一（Rails / PostgreSQL）
- CI（Rubocop + RSpec の足場、DB込みで完走）
- Render(Docker) を前提にした staging デプロイ土台
- 不変条件を守るための「方式固定」（認可運用ルール、添付/アップロード制限の置き場所、最低限のspec）

### 含まない（非目的）
- 本番監視/運用（アラート、ログ基盤整備などの作り込み）
- パフォーマンス最適化
- **R2接続の実装（永続ストレージ本番化）** ※Epic Xで実施

## 依存関係
- Blocks: B〜F（以降の全機能実装）
- Enables: 以降のPRレビュー安定化（CIでの検知、再現性）

## 検証 / 最小テスト
- [ ] 新規クローンから手順通りに起動できる（dev）
- [ ] CIが落ちずに完走する（PRで自動実行）
- [ ] stagingでトップページ相当が表示できる
- [ ] `GET /up`（または同等）が200

## 進め方（タイムボックス運用 / 打ち切り条件）
- Gate1：CIが回らない限り、Renderに進まない
- Gate2：Renderでトップが出ない限り、R2に触らない（R2はEpic X）
- Gate3：RSpecが重い場合、まず **Policy spec 1本 + 添付必須 1本**で止める（数より方式固定）
