## Body

## 目的
ユーザーごとにデータが完全に分離され、他人のデータを閲覧/操作できない状態（所有権認可）をMVPの基盤として確立する。
以降の全実装で「認可の適用漏れ」が発生した場合、CIで即時検知できるようにする。

## DoD（完了条件）
- [ ] Deviseでログイン/ログアウト/登録が動く
- [ ] 認可方式を固定（Pundit）し、以下の運用を徹底する
  - [ ] index：必ず `policy_scope(Model)` を使用（`Model.all` / `Model.where` 直叩き禁止）
  - [ ] show/new/create/edit/update/destroy：必ず `authorize(record_or_class)` を実行
- [ ] `verify_authorized` / `verify_policy_scoped` を原則ON（適用漏れはCIで失敗）
  - [ ] 例外は `skip_after_action` で明示し、例外一覧をREADME/ADRに記録
- [ ] URL直打ちでも他人のレコードへアクセス不可（一覧/詳細/更新/削除すべて）
  - [ ] 未ログイン：Devise標準（ログインへ誘導）
  - [ ] ログイン済み・非所有：404に統一（存在を示唆しない）
- [ ] 主要リソース（Session/Scene/Asset/Usage/Tag）の所有権が一貫
  - [ ] Session/Asset/Tag：`user_id` により所有
  - [ ] Scene：`scene.session.user_id` により所有（間接所有）
  - [ ] Usage：session/scene も asset も「current_user 所有」からのみ選択/作成できる（混在禁止）
- [ ] ActiveStorage参照方針が固定
  - [ ] 添付のURL生成/表示は「認可済みAsset経由」のみ（blob直露出を避ける）

## スコープ
### 含む
- Devise導入・基本設定
- Pundit導入
- 全アクションへの `policy_scope/authorize` 適用と、適用漏れ検知（verify_*）
- 所有権（current_user前提）でのスコープ設計
- エラーハンドリング方針（非所有は404に統一）

### 含まない
- 管理者ロール、チーム共有、招待機能
- 2FA等の高度な認証

## 受け入れ条件（Yes/No）
- [ ] ログイン後、自分のレコードのみ閲覧/編集/削除できる
- [ ] 他人のIDを指定しても 404 になる（情報漏えいしない）
- [ ] `policy_scope/authorize` の適用漏れはCIで検知される（verify_* により）

## 最小テスト/検証（MVP最小）
- [ ] Policy spec：Session/Asset/Tag/Usage/Scene の所有権（最低でも index/show/create/update/destroy）
- [ ] Request/System：ログイン後、他人データのURL直打ちが404になることを確認
- [ ] CI：認可適用漏れ（verify_*）があると失敗することを確認（少なくとも1ケース）
