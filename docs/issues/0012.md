## Body

# #12 所有権の強制（URL直打ち・改ざんでも混入ゼロ）

## 目的
ユーザーごとにデータが完全に分離され、他人レコードの閲覧/操作が一切できない（所有権認可）状態を主要リソースの全CRUDで保証する。

## スコープ
**含む**
- Pundit Policy/Scope による所有権強制（#11運用ルール前提）
- 一覧系（collection action）は必ず `policy_scope` 起点（他人混入ゼロ、index固定ではない）
- show/update/destroy の他人ID直打ちは 404（#11方針）
- create で他人外部キー混在を拒否（Usage/AssetTag含む）

**含まない**
- 管理者/共有/招待、権限ロール階層
- DB設計の追加変更（Epic C/D/F の制約で担保）
- ActiveStorage 配信の認証化（Authenticated Controllers等）

## 受け入れ条件（Yes/No）
- [ ] 一覧系で他人レコードが混入しない（常に policy_scope 起点）
- [ ] show/update/destroy の他人ID直打ちは 404
- [ ] create で他人外部キー混在（Usage/AssetTag）が成立しない
- [ ] DB例外（FK/UNIQUE等）をユーザーに見せない（404/422に収束、500禁止）

## DoD
- [ ] Session/Asset/Tag は Scope が current_user 所有のみを返す
- [ ] Scene/Usage は「正本（Session/Asset）経由」で所有判定する（ADR参照）
- [ ] Usage/AssetTag の混在禁止を単一箇所（Service）に集約して実装する（ADR参照）
- [ ] verify_policy_scoped / verify_authorized をONにし、呼び忘れゼロ（例外はApplicationController集約）
- [ ] 既存CIがテスト必須の場合に限り、最小の Request spec を追加して安定稼働させる

## 最小テスト/検証（CI安定重視）
- [ ] 他人レコード show 直打ち → 404（Session/Asset/Tag 代表）
- [ ] 一覧系に他人が混入しない（Session/Asset 代表）
- [ ] Usage 作成で混在パラメータ → 失敗（404/422に収束、500にしない）
- [ ] AssetTag 付与で他人 tag 指定 → 失敗（404/422に収束、500にしない）

## 実装ガードレール（MVP固定仕様 / Codex向け）

### kind / role（Controllerは作らない）
- KindsController / RolesController は生成しない（MVP対象外）
- `assets.kind` は enum、`usages.role` は enum（マスタCRUD・画面は作らない）

### Usage（routes / 入力 / 更新範囲）
- routes は Asset 配下にネスト（Asset詳細導線に寄せる）
  - POST   `/assets/:asset_id/usages`        (create)
  - PATCH  `/assets/:asset_id/usages/:id`    (update: role のみ)
  - DELETE `/assets/:asset_id/usages/:id`    (destroy)

- member取得は必ず asset 配下にスコープして 404 に寄せる（`Usage.find(id)` 禁止）
  - `asset = policy_scope(Asset).find(params[:asset_id])`
  - `usage = policy_scope(Usage).where(asset_id: asset.id).find(params[:id])`

- create の入力は `session_id` と `role` のみ（`scene_id` は受け取らない）
  - server-side で default_scene（position=1）を解決して `usage.scene` にセット
- update は `role` のみ更新可（strong parameters も role のみ permit）

### Scene（ベータ固定）
- MVPでは各 Session の Scene は default_scene のみ（position=1）
- default_scene は Session 作成時に自動生成される前提（本Issueでは生成実装は行わない。未実装の場合は別Issueで先に実装する）
- Scene CRUD（複数Scene、position採番、UI/導線）は別Issueで定義・実装する

### パラメータ規約（混在禁止）
- 全リソース共通：`user_id` は permit しない（create は `record.user = current_user` を必ずサーバで代入）
- join系（Usage / AssetTag）の create：
  - 外部キー（`asset_id`, `session_id`, `scene_id`, `tag_id`）は原則 permit しない
  - URL と `policy_scope(...).find`（または Ownership Guard）で解決した record を代入して関連を確定する

### Pundit運用（固定）
- collection action は `policy_scope(Model)` 必須（index以外も同様）
- member action は `authorize(record)` 必須
- member取得は原則 `record = policy_scope(Model).find(params[:id])`（ネストは `where(...).find`）
- verify_policy_scoped / verify_authorized は本IssueでON
- verify除外（Devise/health/PWA/root等）は ApplicationController 側で集約（controller個別skip乱発は禁止）

### verify_policy_scoped の適用方式（index固定にしないための規約）
- collection action は controller 側で明示し、その action では必ず `policy_scope(Model)` を実行する。
- ApplicationController は「controller が宣言した collection action」に対して verify_policy_scoped を適用する。
- 目的：index以外の一覧系 action が増えても scope 漏れを機械的に検知し、呼び忘れゼロを維持する。

### verify の排他運用（必須：Punditの設計に合わせて事故を防ぐ）
- collection action（policy_scope必須）は **verify_policy_scoped を要求**し、**verify_authorized は除外**する。
- member action（authorize必須）は **verify_authorized を要求**し、**verify_policy_scoped は除外**する。
- ApplicationController は「controller が宣言した collection action」を基に、上記の除外/適用を機械的に行う。

### new/create（案A固定：authorize前に所有者を確定）
- new/create は `record = Model.new` → `record.user = current_user`（authorize前）→ `authorize(record)` を固定手順とする。
- 目的：Policy が `record.user == current_user` を前提にしても判定がブレないようにする。

### Usage create の session_id の扱い（混在禁止を崩さないための固定）
- `session_id` は入力として受け取ってよいが、Usageへ **IDを直接代入しない**。
- 必ず `session = policy_scope(Session).find(params[:session_id])` で解決し、`usage.session = session` として関連を確定する。
- 目的：改ざんIDでも save 前に `RecordNotFound`（=404）へ落とし、DB例外に依存しない。

### Finder 規約（404/422収束・500禁止のため）
- 取得は `find` / `where(...).find` を原則とする（見つからない場合は `ActiveRecord::RecordNotFound` をraiseして404に寄せる）。
- `find_by` は原則禁止（nil起因で 500 を誘発しやすいため）。

### 例外収束（#11方針との整合：限定列挙・StandardError禁止）
- `rescue_from StandardError` は禁止
- rescue は ApplicationController に集約し、下記のみ扱う（他はバグとして落とす）
  - 404：`Pundit::NotAuthorizedError`, `ActiveRecord::RecordNotFound`
  - 422：`ActiveRecord::RecordNotUnique`, `ActiveRecord::InvalidForeignKey`, `ActiveRecord::RecordInvalid`, `ActionController::ParameterMissing`
- 方針：他人ID/混在は `policy_scope.find` / ネスト `where.find` で **save前に404** に落とす。422は保険・入力不正・重複の収束に使う。
- 422（`RecordNotUnique` / `InvalidForeignKey` 等）は「本来は上流で潰すが、DB例外が出ても500にしないための保険」として扱う。
