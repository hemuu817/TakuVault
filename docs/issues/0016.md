# Issue #16: Epic D : Asset + Usage（Where used核）

- URL: https://github.com/hemuu817/TakuVault/issues/16
- State: OPEN
- UpdatedAt: 2026-01-11T17:29:41Z
- Labels: relates-to-C, relate-to-X, relate-to-B, relate-to-E

## Body

## 目的
TakuVaultのコア価値「Where used（素材→セッション/シーン/役割の逆引き）」を成立させる。  
アップロード安全性・DB整合性・削除整合性を満たしつつ、Asset詳細で Where used が参照・追加・削除できる状態にする。

---

## DoD（完了条件）

### Asset（添付・分類・作成）
- [ ] **1ファイル=1Asset**（`has_one_attached :file`）で作成できる
- [ ] **複数ファイル投入時**、ファイル数分のAssetレコードが作成される（1ファイル=1Assetを厳守）
- [ ] **ActiveStorage参照は認可済みAsset経由のみ**
  - [ ] 添付URL生成/表示は必ず `authorize @asset` 後に行う（blob直露出を避ける）
- [ ] `assets.kind` をMVPに含める（分類の自動決定）
  - [ ] `kind` は enum（int）/ NOT NULL / default: `other`
  - [ ] 添付の `content_type`（一次情報）から自動決定（例：`image/audio/video/other`）
  - [ ] 判定ロジックはモデル（または専用サービス）に集約し、Controller/Helperへ分散させない

### アップロード安全性（サーバ側強制）
- [ ] **アップロード制限（Content-Type / 拡張子 / サイズ）**をサーバ側で拒否（クライアント依存NG）
- [ ] **失敗時に中途半端なデータが残らない**
  - [ ] 1ファイル単位で原子性：失敗したファイルは **Asset/Attachment/Blob を残さない**
  - [ ] 複数ファイル投入時：**成功分のみ作成**、失敗分は0件（レコードも添付も無し）

### Usage（Where used 付与）
- [ ] Usageが作成/削除できる（`asset + session + scene + role`）
- [ ] `scene_id` は **NOT NULL**（Epic Cの default_scene: position=1 により NULL を発生させない）
- [ ] `role` は **許容値固定（enum等） + NOT NULL**
- [ ] 重複登録できない（DBで拒否）
  - [ ] `UNIQUE(asset_id, session_id, scene_id, role)` が成立
- [ ] session–scene 整合がDBで保証される（改ざん/URL直打ち対策）
  - [ ] `usages(session_id, scene_id) -> scenes(session_id, id)` の **複合FK**
  - [ ] 上記成立のため `scenes` に `UNIQUE(session_id, id)` が存在
- [ ] 所有権整合が崩れない（混在禁止）
  - [ ] Usage作成時に **asset と session/scene が current_user 所有**であることを強制（policy_scope + サーバ再検証）
  - [ ] policy_scope外のIDを渡しても作成できない（404/422等、方針に合わせる）

### 表示（Where used 逆引き）
- [ ] Asset詳細に Where used 一覧が表示される（追加/削除が即反映される）
- [ ] 表示項目と並び順が固定されている（例：`session > scene.position > role`）
- [ ] 一覧表示でN+1を起こさない（必要に応じて `includes`）

### 削除整合性
- [ ] Asset削除で Usage も削除される（整合性が崩れない）
- [ ] 添付は `purge_later` 前提で整合（Attachment/Blobが残骸化しない）
- [ ] Session削除 → 配下Scene/Usage削除（Assetsは残す）
- [ ] Scene削除（default以外）→ 配下Usage削除（default_scene=position=1はEpic Cで削除不可）
- [ ] DB/ARのどちらかに寄せて矛盾させない（推奨：DB CASCADE）

## スコープ

### 含む
- Asset CRUD + ActiveStorage添付（1ファイル=1Asset、複数投入対応）
- `assets.kind` 自動決定（content_typeベース）
- Usage CRUD（Where used付与/削除）
- 削除ポリシー整合（Asset削除→Usage削除、Session/Scene削除時の整合）
- DB制約（UNIQUE, FK, NOT NULL, index 等）
- 認可（所有権）を前提にしたCRUD（policy_scope/authorize）

### 含まない
- ActiveStorage Direct Upload（MVPはサーバ経由multipart固定）
- 変換（動画→APNG等）
- 自動分類（role推定、用途推定などの推測系）
- 複数ツール対応（Cocofolia以外）

---

## 受け入れ条件（Yes/No）

### アップロード
- [ ] アップロード成功時、一覧/詳細で参照できる（認可済みAsset経由）
- [ ] アップロード失敗時、**中途半端なAsset/添付（Attachment/Blob含む）が残らない**
- [ ] 複数ファイル投入時、成功分のみ作成され、失敗分は0件

### kind
- [ ] 添付の `content_type` に応じて `kind` が自動で確定し、`kind` は常にNOT NULL

### Usage
- [ ] Usageが登録でき、Asset詳細に表示される
- [ ] Usage重複は作れない（DB制約で拒否される）
- [ ] `scene_id` は必ず埋まる（default_scene運用によりNULLが発生しない）
- [ ] session–scene が不整合（sceneが別session所属）の場合、Usage作成は拒否される（DB or 422）
- [ ] 他人のasset/session/sceneを指定しても作成できない（混在禁止）

### 削除整合
- [ ] Asset削除でUsageも消える（整合性が崩れない）
- [ ] Session削除で配下Scene/Usageが消える（Assetsは残る）
- [ ] Scene削除（default以外）で配下Usageが消える

---

## DB要件（明示）
- assets:
  - [ ] `user_id NOT NULL`（所有権）
  - [ ] `kind NOT NULL`（enum/int、default: other）
- usages:
  - [ ] `asset_id NOT NULL`（FK）
  - [ ] `session_id NOT NULL`（FK）
  - [ ] `scene_id NOT NULL`（FK）
  - [ ] `role NOT NULL`（enum/int）
  - [ ] `UNIQUE(asset_id, session_id, scene_id, role)`
  - [ ] `FOREIGN KEY (session_id, scene_id) REFERENCES scenes(session_id, id)`（複合FK）
- scenes:
  - [ ] `UNIQUE(session_id, id)`（複合FK参照先一意性）
- 削除:
  - [ ] `Asset削除 -> Usage削除`（CASCADE推奨）
  - [ ] `Session削除 -> Scene/Usage削除`（CASCADE推奨）
  - [ ] `Scene削除(default以外) -> Usage削除`（CASCADE推奨）

## 最小テスト/検証（MVP最小）

### Model / DB
- [ ] 添付必須（未添付は無効）
- [ ] サイズ上限 / Content-Type / 拡張子の拒否（サーバ側）
- [ ] `assets.kind` 自動決定（image/audio/video/other） + NOT NULL
- [ ] `UNIQUE(asset_id, session_id, scene_id, role)` が効く（重複で例外/エラー）
- [ ] 複合FK（`usages(session_id, scene_id)`）が効く（不整合で作成不可）

### Policy
- [ ] Asset/Usage の所有権（他人のレコードは閲覧/操作不可）
- [ ] Usage作成で「他人asset×自分session」など混在が通らない

### System（CI安定重視）
- [ ] 複数選択アップロード → 複数Asset作成（file input複数選択で実施）
- [ ] Usage追加 → Asset詳細にWhere used表示
- [ ] Usage削除 → 詳細から消える
- [ ] D&Dは手動QA（ブラウザ依存のためCIに入れない）
