# Issue #24: (19) Asset削除整合性

- URL: https://github.com/hemuu817/TakuVault/issues/24
- State: OPEN
- UpdatedAt: 2026-01-15T12:35:20Z
- Labels: 

## Body

## 目的（このIssueで達成する価値）
素材（Asset）を削除したときに、関連Usageが確実に削除され、添付ファイルが purge_later されることで、DB整合性と所有権安全性を崩さない。

## スコープ
**含む**
- 削除ポリシー（固定）
  - Asset削除 → 関連Usage削除 → 添付ファイル purge_later
- DB整合性（本Issueで確定）
  - usages.asset_id の外部キーを **ON DELETE CASCADE** にする（DBがUsageを消す）
  - AR側で usages に dependent を付けて二重管理しない（DB CASCADE に寄せる）
- ActiveStorage（purge_later の保証）
  - Asset は has_one_attached（1ファイル=1Asset）を前提とし、**dependent: :purge_later を明示**する
  - controller の削除は `destroy` を使用する（`delete` は使用しない）
- 認可（所有権）
  - Asset削除は Pundit authorize により所有者のみ実行可能（URL直打ち含む）
- UX（最小）
  - 削除成功：素材一覧へリダイレクト + 成功フラッシュ
  - 削除失敗：同画面へ戻す/エラー表示（実装都合で統一）
  - confirm は簡潔な文言でOK（必須）

**含まない**
- Session/Scene/Tag 削除の整合性（別Issue）
- 署名URLの無効化やプロキシ配信（MVP外）
- R2上の残骸監査/バッチGC（将来）

## 受け入れ条件（Yes/No）
- [ ] 自分のAssetを削除すると、関連するUsageがDB上からすべて削除される（ON DELETE CASCADE）
- [ ] 自分のAssetを削除すると、添付ファイルの purge_later 相当のジョブが enqueue される（実ファイル削除完了までの同期は不要）
- [ ] 他ユーザーのAsset削除URL直打ちは拒否される（Pundit）
- [ ] Asset削除後に参照切れが残らない（Usageが残存しないため、Where used/セッション素材一覧で例外が起きない）
- [ ] 既に削除済みのAssetに対して削除を再実行しても致命的に落ちない（RecordNotFound等で安全に終了。HTTP扱いは全体方針に従う）

## DoD（完了条件）
- [ ] DB（structure.sql）に ON DELETE CASCADE が反映されている
- [ ] controller で `destroy` を使用し、Pundit authorize が入っている
- [ ] System/Model テストで「Usage消滅」「purge_job enqueue」「認可NG」を担保する

## 失敗ケース（最低3つ）
- [ ] Assetは消えたがUsageが残り、画面で参照切れ／例外が起きる
- [ ] Usageは消えたが purge_later が走らず、添付（blob）が残り続ける（ジョブ未enqueue）
- [ ] 認可漏れで他ユーザーのAssetが削除できてしまう

## 最小テスト/検証
**Model/DB**
- [ ] Assetを削除すると、usages がDB上から削除される（ON DELETE CASCADE の確認）
- [ ] 外部キー制約により、削除時に例外が出ない（整合が保たれる）

**Policy**
- [ ] AssetPolicy#destroy? が所有権で拒否できる
- [ ] policy_scope(Asset) 起点で他人のAssetが参照できない

**System**
- [ ] 自分のAssetを削除すると、一覧から消える
- [ ] 削除後、そのAssetのUsageが存在しない（Where used/セッション素材一覧で出ない）
- [ ] purge_later 相当のジョブが enqueue される（実ファイル削除完了までは追わない）
- [ ] 他人のAsset削除は拒否される
- [ ] 削除を2回叩いても致命的に落ちない（削除済みの扱いは全体方針に従う）
