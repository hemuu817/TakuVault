# #24 Asset削除整合性（Usage削除 + 添付purge_later）

## 目的（このIssueで達成する価値）
素材（Asset）を削除したときに、関連するUsageと添付ファイルが一貫して削除され、DB整合性と所有権安全性が崩れないようにする。

## スコープ
**含む**
- Asset削除の振る舞いを固定する
  - Asset削除 → 関連Usage削除 → 添付ファイル purge_later（ActiveStorage）
- 認可：Asset削除は Pundit authorize で所有者のみ実行可能（URL直打ち含む）
- DB/AR整合性のいずれかに寄せて矛盾させない（推奨：DB CASCADE）
  - usages.asset_id は ON DELETE CASCADE を適用（または AR dependent: :destroy を採用する場合はDB側を合わせる）
- 失敗時の整合性
  - purge_later は非同期のため、レコード削除後も blob が即時消えないことは許容
  - ただし Usage が残る／別ユーザーの参照が残る等の“参照整合性破壊”は許容しない
- 画面/UX
  - Asset削除後は素材一覧へリダイレクトし、成功/失敗のフラッシュを表示する
  - 削除確認（confirm）を表示する（文言はMVP相当で簡潔に）

**含まない**
- Session削除/Scene削除/Tag削除の整合性（それぞれ別Issueの責務）
- 添付のウイルススキャン等（MVP外）
- 物理ストレージ（R2）上の残骸監査やガーベジ回収（将来）

## 受け入れ条件（Yes/No）
- [ ] 自分のAssetを削除すると、関連するUsageがすべて削除される
- [ ] 自分のAssetを削除すると、添付ファイルが purge_later で削除される
- [ ] 他ユーザーのAsset削除URL直打ちは拒否される（Punditで拒否）
- [ ] Asset削除後、Where used（使用先）に参照切れが残らない（Usageが残存しない）
- [ ] 削除操作は二重送信により二重実行されても破綻しない（2回目は404/許容エラー等で安全に終わる）
- [ ] 削除後は素材一覧へ戻り、成功/失敗が分かる

## DoD（完了条件）
- [ ] DB/ARの削除方針が一貫している（CASCADE or dependent を混在させない）
- [ ] Policy と System spec で所有権・整合性が担保される
- [ ] 主要な失敗ケース（権限なし、既に削除済み、添付なし等）で例外が起きない

## 失敗ケース（最低3つ）
- [ ] Assetは消えたがUsageが残り、画面で参照切れ／例外が起きる
- [ ] Usageは消えたがAsset添付blobが残り続け、ストレージ肥大化する（purge未実行）
- [ ] 認可漏れで他ユーザーのAssetが削除できてしまう

## 最小テスト/検証
**Model/DB**
- [ ] usages.asset_id に ON DELETE CASCADE（または同等の整合方針）があることを検証
- [ ] UNIQUE/FK制約違反が削除時に発生しない

**Policy**
- [ ] AssetPolicy#destroy? が所有権で拒否できる
- [ ] policy_scope(Asset) 起点で他人のAssetが参照できない

**System**
- [ ] 自分のAssetを削除すると、Assetが一覧から消える
- [ ] 削除後、そのAssetのUsageがDB上から消える（Where used に出ない）
- [ ] 他人のAsset削除は拒否される
- [ ] 削除を2回叩いても致命的に落ちない（404等で安全に終わる）
