## Body

## 目的（このIssueで達成する価値）
ログインユーザーが、素材（Asset）を安全にアップロードし、一覧/詳細参照・名称変更（display_name）・削除までの最小CRUDを実行できる。

## 前提（関連決定事項）
- `assets.kind` / `usages.role` は enum として扱う（プロジェクト決定事項）。ただし本Issueでは `assets.kind` の自動判定・設定は行わない（別Issue/ADR-0002）。
- Usage の routes は `assets -> usages` ネストが正（プロジェクト決定事項）。ただし本Issueでは UsagesController/導線は実装しない（別Issue）。

## スコープ
### 含む
- Asset CRUD（index/show/new/create/edit/update/destroy）
- 添付必須（最低1ファイル）
- Asset は **1ファイル=1Asset**（`has_one_attached` 前提）
- **複数ファイル一括アップロード（MVP必須）**
  - ドラッグ&ドロップで複数ファイル選択できる
  - フォールバックとして「ファイル選択（複数）」でも同等にアップロードできる
  - 複数選択時は **ファイル数分の Asset レコードを作る**
- アップロード方式：**サーバ経由 multipart**（Direct Upload 不採用）
- `display_name` 保存（未入力時は `original_filename` を自動採用）
- `original_filename` を Asset 側へ保存（添付時にコピー、以後不変）
- 認可：自分の Asset のみ（Pundit の `policy_scope` / `authorize` を徹底）
- 参照URL：**認可済み Asset からのみ URL 生成**（リンク露出＝認可境界）
- バリデーション/拒否：サーバ側で実施（クライアント依存禁止）

### 含まない
- `assets.kind` の自動判定・永続化（別Issue / ADR-0002）
- Usage 連動削除、`purge_later` を含む物理削除の整合（別Issue： (16) Asset削除整合性）
- storage.yml / production.rb / Render設定（R2・Solid Queue等の環境構成）の変更（別Issueの責務）
- 検索／絞り込み／タグ／モーダル化
- 変換／プレビュー生成等

## 参照（仕様の正本）
- ADR-0012：ActiveStorage運用の正本（R2 service / Solid Queue / サーバ経由multipart統一）
- ADR-0013：容量・上限（1ファイル/1回/総容量、算定、排他、all-or-nothing）
- ADR-0014：許可形式・判定方式・エラーハンドリング（実体MIME+拡張子AND、422/413、ログ）
- ADR-0002：Asset.kind（本Issueでは扱わない）

## 受け入れ条件（Yes/No）
- [ ] 未ログインでは Asset にアクセスできない（一覧/詳細/作成/更新/削除）
- [ ] 自分の Asset のみ CRUD できる（URL直打ち含む、fail-closed）
- [ ] 複数ファイル選択アップロードができ、**ファイル数分の Asset** が作成される（1ファイル=1Asset）

### 0件送信（Railsのhidden空要素混入も含めて）を弾く
- [ ] 0件送信は 422（未入力）で拒否される
- [ ] `file_field multiple: true` が送る hidden の空要素のみの場合も **0件扱い**になる
  - 実装は「`include_hidden: false` を指定」または「サーバ側で blank を除外して件数判定」のいずれでもよい

### 形式/上限/容量の拒否（ADR準拠）
- [ ] 許可外形式は 422（形式不正）で拒否される（判定は ADR-0014 正本）
  - `identify: false` は使わず、サーバ側の同定をスキップしない
  - 同定不能（`application/octet-stream` 等）は不許可扱い
- [ ] サイズ/件数/容量（1ファイル/1回/総容量）は ADR-0013/0014 の通り拒否される
- [ ] 上限値（1ファイル/1回/総容量/件数）は **ADR-0013 の固定値**に従う（本Issue本文には再掲しない）
- [ ] 件数（30）超はコントローラ層で早期に 422（件数超過）として拒否する（多層防御）
- [ ] 総容量（500MB）判定はユーザー行ロック等で排他し、同時アップロードでも上限超過状態を残さない
- [ ] **all-or-nothing**：同一リクエスト内で1件でも不正なら、作成結果は **Asset 0件**（部分成功なし）
  - 失敗時に「Asset と Attachment が作られない」ことを保証する（孤児Blob/孤児オブジェクトの扱いは ADR-0013 に従う）

### ステータス/表示
- [ ] アプリ側で検知できた拒否は原則 422（理由表示）
- [ ] プラットフォーム制限等でアプリに到達しない場合は 413 を許容（理由表示不可の例外として扱い、docsに明記）

### destroy の期待値（#16との境界）
- [ ] destroy 後、アプリの導線（`assets/:id` 等）から参照不能になる
- [ ] 物理 purge / Usage 連動等は (16) の正本に従う（本Issueでは実装しない）
- [ ] 既に発行済みの署名付きURLが一定時間有効であることは許容（MVP対象外）

## DoD（完了条件）
- [ ] routes / controller / policy / views が揃い、手動QAで CRUD が一通り動作する
- [ ] `policy_scope` 起点で取得し、他人の Asset は fail-closed になる
- [ ] ADR-0013/0014 の拒否条件に整合し、拒否理由（区分）がログに残る

## 失敗ケース（最低3つ）
- [ ] 0件送信（hidden空要素のみ含む）→ 422
- [ ] 許可外形式（実体MIME/拡張子不一致、同定不能含む）→ 422
- [ ] 上限超過（1ファイル/1回/総容量）→ 422（到達する場合）/ 413（到達しない場合）
- [ ] 他人の assets/:id URL直打ち → 404（fail-closed）
