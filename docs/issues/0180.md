# Issue #180: （46）JavaScriptテスト基盤導入

- URL: https://github.com/hemuu817/TakuVault/issues/180
- State: OPEN
- UpdatedAt: 2026-09-07T08:40:37Z
- Labels: 

## Body

## 目的

ADR-0020「JSテスト移行とRSpecの債務境界」に基づき、TakuVaultへJavaScript専用のテスト基盤を導入する。

本番のImportmap構成を維持したまま、Stimulus Controllerの挙動を以下の2層で検証できる状態を成立させる。

- Vitest + jsdomによるJavaScript単体 / DOMテスト
- Vitest Browser Mode + Playwrightによる実ブラウザテスト

ローカルとCIでは同じDockerベースのJavaScriptテスト環境を使用し、テスト実行環境の差異を抑える。

本Issueではテスト基盤の成立を目的とし、既存RSpec System Specの責務再配置・削減は後続Issueで扱う。

## 背景

現在のTakuVaultでは、本番JavaScriptをImportmapで配信し、Stimulus Controllerを利用している。

一方、JavaScript専用のテスト基盤は存在せず、JavaScriptの詳細な挙動についても主にRSpec System Spec、Selenium、Chromeを通して検証している。

ADR-0020では、テストの責務を以下へ分離する方針とした。

- サーバー側契約：RSpec Request Spec
- ブラウザ固有機能を必要としないJavaScript：Vitest + jsdom
- ブラウザ固有のJavaScript：Vitest Browser Mode
- Rails / DB / Turbo / JavaScriptを横断する主要導線：RSpec System Spec

今後のモーダル実装では、フォーカス、キー入力、イベント伝播などのJavaScript挙動を検証する必要がある。

そのため、既存System Specの全面的な責務再配置に先行して、JavaScriptテストを適切な層で実行できる基盤を成立させる。

## 前提 / 実装順

本Issueは、ADR-0020がAcceptedになった後に実装する。

実装順は以下を基本とする。

1. ADR-0020をAcceptedにする
2. 本IssueでJavaScriptテスト基盤を成立させる
3. 本Issue完了後、モーダル実装へ進行可能とする
4. 既存System Specの責務再配置は別Issueで行う

既存System Specの責務再配置完了を、本Issueまたはモーダル実装の必須前提にはしない。

## スコープ

### 含む

#### Node.js / npm

JavaScriptテスト環境の基準として以下を使用する。

- Node.js 24.20.0
- npm 11.19.0

以下を追加する。

- `.node-version`
- `package.json`
- `package-lock.json`

`package-lock.json`はリポジトリで管理する。

CIでは依存関係のインストールに`npm ci`を使用し、`package.json`と`package-lock.json`の不整合を許容しない。

#### JavaScriptテスト依存

以下を導入する。

- Vitest 5.0.0
- `@vitest/browser-playwright` 5.0.0
- jsdom 30.0.0
- Playwright 1.63.0
- `@hotwired/stimulus` 3.2.2

npm側の`@hotwired/stimulus`は、現在の`stimulus-rails` 1.3.4で本番配信されるStimulus 3.2.2と揃える。

`@hotwired/stimulus`だけを本番側から独立して更新しない。

将来`stimulus-rails`を更新する場合は、本番で配信されるStimulusのバージョンを確認し、npm側との整合を再確認する。

#### ローカルテスト環境

JavaScriptテストの正式なローカル実行経路はDocker Composeとする。

JavaScriptテスト専用のDocker環境を追加し、以下をコンテナ内で固定する。

- Node.js
- npm
- JavaScriptテスト依存
- Playwright
- Chromium
- ブラウザ実行に必要なOS依存

ホストOS上でNode.js / npmを直接利用する実行方法は、正式なサポート対象およびAC / DoDの検証経路に含めない。

ローカルとCIでは同じJavaScriptテスト用Docker環境を使用する。

#### JavaScriptテスト配置

JavaScriptテストはRSpecから分離し、`test/javascript/`配下へ配置する。

基本構成は以下とする。

```text
test/javascript/
├── controllers/
├── browser/
└── support/
```

各ディレクトリの責務は以下とする。

- `controllers/`
  - Vitest + jsdomで検証するStimulus Controller等
- `browser/`
  - Vitest Browser Modeで検証する実ブラウザ依存処理
- `support/`
  - Stimulus起動・停止、fixture等の共有テスト処理

#### 命名

JavaScriptテストのファイル名は、原則としてテスト対象となる既存JavaScriptファイル名へ対応させる。

例：

```text
app/javascript/controllers/foo_controller.js
↓
test/javascript/controllers/foo_controller.test.js
```

実ブラウザテストもテスト層をディレクトリで区別する。

```text
test/javascript/browser/foo_controller.test.js
```

`.browser`等の層名をファイル名へ重複して付与することは原則行わない。

特定の本番ファイルと一対一対応しない共有処理は`test/javascript/support/`へ配置する。

#### Stimulusテストヘルパー

`test/javascript/support/`にStimulus Controllerテスト用の共有処理を整備する。

最低限、以下を扱う。

- Stimulus Applicationの開始
- 本番Controllerの登録
- fixture DOMの設定
- Stimulus接続完了までの待機
- Applicationの停止
- fixture / DOMの後片付け

テスト対象Controllerは`app/javascript/controllers/`から直接importする。

Controllerのロジックをテスト用に複製・再実装しない。

#### Vitest構成

Vitestでは以下を独立したprojectとして扱う。

- jsdom
- browser

jsdom projectは、ブラウザ固有機能を必要としないJavaScriptの判断処理およびDOM状態変更を担当する。

主な検証対象：

- 属性
- class
- disabled
- hidden
- DOM順序
- 選択状態
- Stimulus Controllerの条件分岐

browser projectはVitest Browser Mode + Playwright providerを使用する。

主な検証対象：

- キーボード操作
- フォーカス
- イベント伝播
- スクロール
- ブラウザAPIに依存する挙動

CI上の必須ブラウザはChromiumとする。

Firefox / WebKitは本Issueの必須対象に含めない。

#### 試験導入

新しい基盤がTakuVaultの本番Controllerを実際に検証できることを確認するため、以下を試験対象とする。

##### uncategorized_kind_controller

Vitest + jsdomで検証する。

既存System Specが担っているJavaScript責務のうち、Controller単体およびDOM状態として検証可能な範囲を対象とする。

##### horizontal_scroll_controller

Vitest Browser Mode + Playwrightで検証する。

少なくとも、アプリケーションが実装している以下の挙動を実ブラウザで確認する。

- 対象キー入力による横スクロール
- 対象外キーではスクロールしない
- modifier付き操作を対象外とする既存挙動
- 子要素由来のキーイベントを対象外とする既存挙動
- 横方向にoverflowしていない場合の既存挙動

本Issueでは、対応する既存System Specを削除・縮小しない。

#### CI

JavaScriptテストを既存RSpecとは独立した実行単位とする。

少なくとも以下を分離する。

- JavaScript単体テスト
- JavaScript実ブラウザテスト
- npm依存関係の脆弱性検査

JavaScript単体テストでは、実ブラウザのインストールを必須としない。

実ブラウザテストではPlaywright管理下のChromiumを使用する。

各Jobは、対象テストが失敗した場合にCIを失敗させる。

#### Browser Modeの診断情報

Browser Modeでは、失敗時の調査に必要な診断情報を保存する。

- traceはretain-on-failure
- failure screenshotは失敗時に保存
- 成功したテストのtraceは保存しない
- CI artifactの保持期間は7日

初期導入では常時trace取得を行わない。

#### npm依存関係のセキュリティ

既存の`bin/importmap audit`は維持する。

npmで管理する依存関係について、別途`npm audit`をCIで実行する。

少なくともhigh / criticalの脆弱性をCI失敗として扱う。

CI上で`npm audit fix`を自動実行しない。

#### Dependabot

既存Dependabot設定へnpm ecosystemを追加する。

既存Bundler設定と同様、原則以下とする。

- weekly
- Monday
- 09:00
- Asia/Tokyo
- minor / patch更新をグループ化
- major updateを自動更新PRの対象外とする

`@hotwired/stimulus`の更新は、本番`stimulus-rails`側との整合を確認せずにマージしない。

### 含まない

- 既存RSpec System Specの削除・縮小
- 既存System Spec全体の保証内容棚卸し
- 既存System SpecからRequest Spec / jsdom / Browser Modeへの本格的な責務再配置
- モーダル機能そのものの実装
- ネイティブ`<dialog>`採用可否
- Firefox / WebKitをCI必須ブラウザとすること
- 本番JavaScript配信方式の変更
- Vite / esbuild等の本番JavaScriptビルド基盤導入
- Node.jsを本番実行環境へ導入すること
- ホストOS上でのJavaScriptテスト実行の正式サポート
- JavaScriptテストJobのrequired check化
- Branch Protection / ruleset運用全体の変更
