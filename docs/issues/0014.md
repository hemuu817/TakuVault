# Issue #14: (7) Session CRUD(cocofolia固定+room_url参照)

- State: OPEN
- UpdatedAt: 2026-01-11T18:57:29Z

## Body

## 目的
- セッションを作成/参照/更新/削除できる（所有権を満たす）
- room_url を安全に参照できる（http/https制限 + 安全リンク属性）
- MVPではツールはCocofolia固定だが、将来拡張のため tool_variant を先行導入し、**DBで仕様違反を防ぐ**

## DoD
- [ ] Session CRUD が動作し、`policy_scope/authorize` で所有権が徹底されている（URL直打ち含む）
- [ ] Session作成は transaction で完結し、作成時に `default_scene` が自動作成される
- [ ] `room_url` は「空OK・入力時のみhttp/https許可（trim）」で検証される
- [ ] Session詳細の room_url はリンク表示され、`target=_blank` + `rel=noopener noreferrer` が付与されている
- [ ] MVP固定：`tool_variant` は **DB CHECK で `=1（cocofolia）` を強制**（改ざんでも混入しない）
- [ ] Session削除で配下 Scene/Usage が削除される（Assetsは残る）（方式固定：**DB CASCADE**）
- [ ] 最小テスト（Model/Policy/System）が揃っている（不正アクセス/不正URL/改ざん含む）

## スコープ
### 含む
- Session：index/show/new/create/edit/update/destroy（MVPはCocofoliaのみ）
- tool_variant（将来拡張前提で先行導入）
  - DB：`integer NOT NULL DEFAULT 1` + **CHECK `tool_variant = 1`**（MVP中のみ）
  - Rails：enum（`cocofolia: 1`）。strong params で受け取らず、作成時に `cocofolia` をセット
  - UI：ツール欄は表示するが **disabled（Cocofoliaのみ）**。注記「MVPはCocofoliaのみ。将来追加予定」
- room_url
  - 型：text（長文を想定）
  - バリデーション：空OK、入力がある場合のみ http/https を許可（trim）
  - 表示：安全リンク属性付き（host allowlistはMVP外）
- default_scene 自動生成（Session作成時）
  - `is_default=true`、`position=1` を占有（ユーザー作成Sceneは2から：Issue(8)と整合）
- DB整合性（列挙・DB CASCADE前提）
  - `sessions.tool_variant`：NOT NULL/DEFAULT + CHECK（=1固定）
  - `scenes.session_id -> sessions.id ON DELETE CASCADE`（Scene/Usage削除整合性の土台）
  - （存在する場合）`usages.session_id -> sessions.id ON DELETE CASCADE`
  - `usages(session_id, scene_id) -> scenes(session_id, id) ON DELETE CASCADE`（複合FK前提）
- 削除整合性
  - Session削除 → Scenes/Usages削除（Assetsは残す）

### 含まない
- Cocofolia API連携/同期
- tool_variant の複数選択（MVPでは1択固定。将来の制約解除で対応）
- room_url の host allowlist
- Session詳細でのUsageグリッド等の重い表示（別Issue）

## 受け入れ条件（Yes/No）
- [ ] Sessionを作成でき、作成直後に default_scene が必ず存在する
  - [ ] default_scene は `is_default=true` かつ `position=1`
- [ ] `tool_variant` は常に `cocofolia(=1)` で保存される（パラメータ改ざんでも混入しない）
- [ ] room_url が空なら保存できる／入力がある場合 http/https 以外は保存できない（422でエラー表示）
- [ ] Session詳細に room_url がリンクで表示され、`target=_blank` + `rel=noopener noreferrer` が付与されている
- [ ] 他人のSessionにアクセスすると **404** になる（方式固定）
- [ ] Sessionを削除すると配下 Scene/Usage が消える（Assetsは残る）

## 依存 / 関連
- Depends on：認証（Devise）、認可方式固定（Pundit）
- Related：Sub-Issue(8) Scene CRUD（default_scene不変/position採番/制約）、D系（Usage/削除整合性）

## 実装メモ（方式固定）
- 認可：index=policy_scope、show/update/destroy=authorize、他人IDは404統一
- tool_variant
  - strong params で受け取らない（上書き固定）
  - DB CHECK（=1）が最終防衛線（structure.sql前提）
- Session作成（transaction）
  - Session作成と default_scene 作成を同一transactionで実施（半端状態防止）
- default_scene仕様（Issue(8)と一致）
  - `is_default=true`、`position=1`（固定）
- room_url
  - 空OK、入力時のみhttp/https許可（trim）
  - 表示リンクに安全属性付与
- 削除整合性
  - DB CASCADE で統一（Session→Scenes→Usagesの順で消える設計に寄せる）

  - [ ] show/destroyで他人ID直打ちが404

  - [ ] showで room_url の安全リンク属性確認
  - [ ] destroyで Sessionが消える（配下が残らないことを最小限確認）
