# 既存ERB画面のTailwind retrofit

- Phase: **Phase 1**
- Status: **Ready**（機能側の依存はすべてClosed。唯一の着手ゲートは Issue 1「Tailwind CSS導入・ビルド基盤整備」の完了）

## 目的

既存の素のERB画面をTailwind CSSで最低限読みやすい見た目に整え、後続のモーダル化・統合画面化・検索/タグ実装に進む前のUI土台を作る。

このIssueは **見た目のretrofit** を目的とする。
既存機能・既存導線・DB構造・認可境界は変更しない。

## 前提

- Issue 1「Tailwind CSS導入・ビルド基盤整備」が完了している
  - `tailwindcss-rails` によるTailwind CSS利用基盤が存在する
  - ローカルDocker環境でTailwind CSSが反映される
  - Render preview環境（ADR-0011：単一環境 / `RAILS_ENV=production`）でTailwind CSSが反映される
  - Render build command 側のTailwind build反映は **Issue 1 のDoDの責務**であり、本Issueでは変更しない
- 以下の機能Issueはすべて実装済み（Closed）で、対象ビューが実在する前提とする：
  - GitHub #19 / docs/issues/0019.md：Asset CRUD（ActiveStorage）
  - GitHub #24 / docs/issues/0024.md：Asset削除整合性
  - GitHub #14 / docs/issues/0014.md：Session CRUD
  - GitHub #15 / docs/issues/0015.md：Scene CRUD+position
  - GitHub #21 / docs/issues/0021.md：Usage作成
  - GitHub #22 / docs/issues/0022.md：Asset詳細 Where used
  - GitHub #136 / docs/issues/0136.md：Session詳細「セッション素材一覧」

対象ビューが実ファイルとして存在しない場合、本Issue内で前提機能を新規実装しない。
その場合は当該ビューのみ対象外とする（後述のBLOCKED条件は Issue 1 未完にのみ適用）。

## スコープ

### 含む

- 既存ERB画面にTailwind CSSクラスを追加し、最低限読みやすいUIに整える
- `app/views/layouts/application.html.erb` の共通レイアウトを整える
  - 画面全体の余白 / 最大幅 / 背景 / 見出し / ナビゲーション / flash notice・alert
- 主要な `link_to` / `button_to` / submit button の見た目を最低限統一する
- form label / input / select / file_field を最低限読みやすくする
- 一覧画面をカードまたはテーブル風に整える
- Asset詳細の表示を読みやすくする
- Asset詳細の使用先（Where used）表示を読みやすくする
- Session詳細の「セッション素材一覧」を読みやすくする
- Scene関連画面を最低限読みやすくする
- スマートフォン幅でも主要画面が最低限読めるようにする
- Tailwindクラス追加に伴い、必要最小限のHTML構造整理を行う
