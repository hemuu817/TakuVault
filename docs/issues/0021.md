# #21 Usage作成（Where used 付与：一括作成 / 冪等 / fail-closed）

## 目的（このIssueで達成する価値）
未整理（Usage0）のAssetに対して、`session / scene / role` を指定して Usage を**一括作成**でき、Where used の核となる「付与」が安全に成立する状態にする。

## スコープ
**含む**
- Usageの**一括作成（bulk）**（主導線：未整理（Usage0）で複数選択→一括付与）
- **Secondary導線**：Asset詳細（Where used）から `session / scene / role` を指定してUsageを1件追加
- 付与単位は `asset + session + scene + role`（`scene_id NOT NULL`）
- `role` は enum（許容値固定）/ NOT NULL
- **冪等**：重複はスキップし、全体失敗させない（500にしない）
- **fail-closed**：所有権/不正ID/不整合は全体中断（1件も作らない）
- session–scene 整合性はDBで保証（複合FK前提）
- 認可（Pundit：policy_scope/authorize）前提で作成処理を実装

**含まない**
- 単発作成（Asset詳細Where usedから1件追加）※別Issueで扱う
- role推定などの自動化（MVP外）
- UI最適化（選択保持、重複行のハイライト等）※必要なら別Issue化

## 仕様（固定）
### role 許容値（MVP固定）
- `background` / `cutin` / `bgm` / `other`

### Secondary導線の重複挙動（固定）
- 重複（同一キー：asset_id, session_id, scene_id, role）は **422で返す**
- Primaryのスキップ（部分成功）とは挙動を分ける（ADR-0006 D4-S参照）


### 部分成功のルール（固定）
- **重複のみスキップ（部分成功OK）**
  - 重複キー：`(asset_id, session_id, scene_id, role)`
  - 競合や既存は「重複」として吸収し、500にしない
- **それ以外は fail-closed（全体中断）**
  - asset_ids に他人のAssetが混入
  - session/scene が他人所有
  - role 無効値
  - session–scene 不整合（別sessionのscene）など整合違反
  - 上記が1件でもあれば **0件作成**で返す（部分成功しない）

### 結果サマリ（最小要件）

- 一括作成後、少なくとも以下が分かる（UI表示方法は問わない）
  - `created_count`（作成件数）
  - `skipped_duplicate_count`（重複スキップ件数）
  - `skipped_assets`（スキップされたAssetの識別情報）
    - 件数のみでは「何が重複したか」不明なため（ADR-0006 D4-P参照）
    - 具体的な表示形式・粒度（Asset名等）は実装時に決定する

## 受け入れ条件（Yes/No）
- [ ] 自分のAsset（複数）を選択し、`session / scene / role` を指定して Usage を一括作成できる
- [ ] `scene_id` は必須（NULLを許容しない）
- [ ] `role` は必須で、許容値以外は 422 相当で拒否される
- [ ] 同一キー（asset_id, session_id, scene_id, role）の重複Usageは作れない（DBで拒否）
- [ ] 一括付与に重複が混じっても全体失敗しない（重複分はスキップされる）
- [ ] 他人の asset_id / session_id / scene_id を1件でも混ぜた場合は fail-closed（0件作成）になる
- [ ] session–scene 不整合（別sessionのscene）では作成できない（DB整合性で拒否）
- [ ] 結果として created_count / skipped_duplicate_count が取得できる
- [ ] Asset詳細（Where used）から session / scene / role を指定してUsageを1件追加できる（Secondary導線）
- [ ] Secondary導線で同一キーの重複Usageを作成しようとすると 422 で返される（スキップしない）


## DoD（完了条件）
- [ ] Usage一括作成処理がサービス等に集約されている（Controller分散なし）
- [ ] 入口で `policy_scope` を起点に対象Assetを確定し、混在は fail-closed で拒否できる
- [ ] session/scene も所有権チェック済み（policy_scope/authorize）
- [ ] DB制約前提の競合（UNIQUE違反）を重複として吸収し、500にしない
- [ ] 失敗時ステータスが適切（422/403/404）で情報漏えいしない
- [ ] structure.sql に反映されている（必要なDB変更がある場合）

- [ ] Secondary（1件追加）でも所有権チェック（policy_scope/authorize）が適用されている
- [ ] Secondary（1件追加）の重複は 422 で返し、500にしない



## 失敗ケース（最低3つ）
- [ ] 重複が1件でも混じると全ロールバックしてしまい、UXが破綻する
- [ ] 他人ID混入でも一部作成されてしまう（所有権混在）
- [ ] role無効値で500になる（例外未処理）
- [ ] session–scene不整合でも作れてしまう（Where usedの整合崩壊）

- [ ] Secondary（1件追加）で同一キーの重複Usageを作成しようとした場合、スキップされず 422 で返される


## 最小テスト/検証
**Model/DB**
- [ ] `scene_id NOT NULL` / `role NOT NULL` が効く
- [ ] `UNIQUE(asset_id, session_id, scene_id, role)` が効く
- [ ] 複合FK：`(session_id, scene_id) -> scenes(session_id, id)` が効く（不整合で作成不可）

**Policy**
- [ ] Usage作成で「assetとsession/sceneがcurrent_user所有」でないと拒否される

**Request/Service（CI安定重視）**
- [ ] 成功：複数asset_ids → created_count=N
- [ ] 冪等：同じ入力を2回 → 2回目は created_count=0 / skipped_duplicate_count=N
- [ ] fail-closed：asset_idsに他人混入 → 0件作成で失敗（部分成功しない）
- [ ] role無効値 → 422
- [ ] session–scene不整合 → 作成不可（DB拒否 or 422に正規化）

**System（最小）**
- [ ] 未整理（Usage0）で複数選択→一括付与→Where used 反映（表示は別Issueでも、整合は確認）
