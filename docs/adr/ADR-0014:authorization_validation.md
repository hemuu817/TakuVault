# ADR-0014：許可形式・判定方式・エラーハンドリング（Validation）※50MB/500MB版（参照先は同じ）

## ステータス
Accepted

## 背景 / 課題
- Content-Type はクライアント申告が混ざるため、申告値に依存すると「サーバ側で拒否」の要件が形骸化する。
- 一方で、MIMEは環境差があるため候補は広めに取る必要がある。
- プラットフォーム側制限により 413 が返る場合、アプリ側で理由を返せない。
- GIFはサイズが小さくてもデコード負荷が高く、MVPでも運用事故要因になり得る。

## 前提（参照）
- Direct Upload 不採用（サーバ経由 multipart 統一）は ADR-0015 を正本とする。


## 許可形式（MVP）

### 画像（許可）
- Content-Type（候補）：`image/png`, `image/jpeg`, `image/webp`
- 拡張子：`.png .jpg .jpeg .webp`

### 画像（不許可：MVP）
- `image/gif` / `.gif`（運用事故リスク低減のためMVPでは除外）

### 音声（許可）
- Content-Type（候補）：`audio/mpeg`, `audio/mp3`, `audio/wav`, `audio/x-wav`, `audio/ogg`, `application/ogg`
- 拡張子：`.mp3 .wav .ogg`

### 不許可（MVP）
- 動画：`video/*`（例：mp4/webm 等）
- アーカイブ：zip/rar/7z
- 実行形式：exe/dmg/pkg/bat/sh 等
- 文書：pdf/docx 等（必要になったら別Issue）

## 判定方針（正本：サーバ側推定）
- Content-Type は **クライアント申告を信用しない**。
- “実体MIME推定” とは、**サーバ側で推定・確定したMIME**を指す。
  - 例：ActiveStorage の identify/analyzer により決定された `blob.content_type`（クライアント申告を正本にしない設定/運用を前提）
- 判定は以下の **AND** を満たす場合のみ許可する：
  - `(実体MIMEが許可候補に含まれる) AND (拡張子が許可拡張子に含まれる)`
- どちらか不一致は拒否。

## エラーハンドリング方針（仕様ブレ防止）
- アプリ側で検知できた拒否は原則 **422 Unprocessable Entity**（画面に理由表示するため）。
  - 理由区分：サイズ超過 / 形式不正 / 件数超過 / 総容量超過
- プラットフォーム制限によりアプリに到達しない場合は **413 Payload Too Large**
  - このケースはアプリ側で理由表示できない旨を docs に明記する。
  - 可能な限り「アプリ上限（50MB）をプラットフォーム上限以下」に保ち、原則はアプリ側で理由を返す思想とする。

## 多層防御（責務の分離）
- コントローラ層：件数（30）を早期拒否（DB/ストレージに触る前）
- サービス層（推奨）：サイズ（50MB）、形式（実体MIME+拡張子）、総容量（500MB）を判定して拒否
- 参照URL：認可済みAssetからのみ生成（認可境界は別Issue/ADRに従う）

## ログ方針
- 拒否時は「どの上限/どの理由で拒否したか」をログに残す（例外握り潰し禁止）。

## 受け入れ条件（Yes/No）
- [ ] 許可形式（候補MIME/拡張子）とMVP不許可が明記されている
- [ ] 実体MIME推定＝サーバ側推定が正本であることが明記されている
- [ ] 422/413 の扱いと、413は理由表示できない例外であることが明記されている
- [ ] 多層防御（コントローラ早期拒否＋サービス層判定）とログ方針が明記されている
